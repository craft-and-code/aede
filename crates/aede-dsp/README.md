# Aède DSP

`aede-dsp` processes decoded audio samples. It has no decoder, audio device, terminal interface, network access, or dependency on the catalog. The first stage accepts finite, interleaved `f32` PCM and applies one gain to every channel of a frame. Gain can change smoothly across calls, so a future gapless player can keep one processing stream across track boundaries.

The crate measures sample peaks and counts samples above full scale. It does not clip them: floating-point PCM retains headroom for later stages, and the eventual output adapter must make an explicit conversion decision. It also does not control system volume. `aede-core::playback::normalization` now chooses a gain from ReplayGain or Opus R128 tags; this crate applies that choice without knowing its source. Decoded loudness measurement remains future work.

The processing call allocates no memory. Invalid samples, incomplete frames, and gains that would overflow `f32` are rejected before the buffer or gain ramp changes. The sample rate and channel count are fixed per `Dsp` instance; create a new one on a format change.

This establishes the sample contract, gain stage, and a 24-band spectrum analyzer for terminal visualization. `aede-core::playback::stream::PcmTrack` supplies progressively decoded, processed PCM blocks and format metadata independently of the output destination; `aede-core::playback::Queue` holds the playing order. The `aede play` command sends these blocks to a shared local output session for ffplay, records listening history, and shows animated bars in an interactive terminal. The output session reuses one process for consecutive files with the same PCM format and reopens it on a format change; that does not yet guarantee gapless audio. A future remote server handler can use the same PCM blocks to transmit audio to the client device; no server audio route exists yet. Playback still uses unity gain; applying selected ReplayGain or R128 values, driving the in-memory queue, and sample-accurate gapless transitions remain future work. Equalization, filtering, spatial processing, and other optional effects can be added as separate processing stages when their sound and controls are specified.
