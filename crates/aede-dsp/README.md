# Aède DSP

`aede-dsp` processes decoded audio samples. It has no decoder, audio device, terminal interface, network access, or dependency on the catalog. The first stage accepts finite, interleaved `f32` PCM and applies one gain to every channel of a frame. Gain can change smoothly across calls, and is used by the local playback stream for metadata normalization.

The gain stage measures sample peaks and counts samples above full scale without clipping, so later DSP stages retain floating-point headroom. Before playback, `gain_with_headroom_db` caps a requested normalization gain using the declared ReplayGain peak or a measured true peak; when neither exists, it assumes a full-scale peak. `Dsp::process_for_output` includes a final `protect_output` call, which hard-clamps any unexpected samples outside [-1, 1] before output and reports how many it changed. In-range samples are untouched. This sample-peak policy does not guarantee true-peak safety or replace a perceptually designed limiter. The crate does not control system volume. `aede-core::playback::normalization` chooses a gain from ReplayGain or Opus R128 tags; this crate applies it without knowing its source. The [`loudness` module](src/loudness.rs) measures integrated programme LUFS and true peak from decoded PCM with the Rust `ebur128` crate. It accepts blocks and format changes without knowing files, tags, or the catalog. `aede-core` decodes tracks, consults FlacCompagnon results, chooses the gain, and caches fresh measurements; `aede-dsp` applies that gain without knowing its source.

The processing and output-guard calls allocate no memory. Invalid samples, incomplete frames, and gains that would overflow `f32` are rejected before the buffer or gain ramp changes. The sample rate and channel count are fixed per `Dsp` instance; create a new one on a format change.

`ToneControls` provides optional broad bass and treble shelves, each limited to ±12 dB. The `biquad` crate implements the W3C Audio EQ Cookbook shelf coefficients with a monotonic slope and one state per channel; coefficients and state are prepared outside the PCM processing call. A flat setting removes the filters for an exact bypass. A boost reserves a conservative preamp of the sum of positive shelf gains, in addition to the existing peak-aware normalization cap. The final output guard remains necessary for transient overshoot and inaccurate peak metadata. The shelves use 120 Hz and 4 kHz midpoints at ordinary sample rates, lowered when necessary to stay below Nyquist. `Dsp::set_tone(ToneControls::FLAT)` resets to bypass; configure a new tone between streams because replacement clears filter state.

This establishes the sample contract, gain and broad tone stages, and a 24-band spectrum analyzer for terminal visualization. `aede-core::playback::stream::PcmTrack` supplies progressively decoded, processed PCM blocks and format metadata independently of the output destination; `aede-core::playback::Queue` holds the playing order. The `aede play` command sends these blocks to a CPAL device stream when its format matches or to ffplay otherwise, records listening history, and shows animated bars in an interactive terminal. Matching-format tracks reuse the output, but physical gapless playback has not been measured on hardware. Playback applies ReplayGain or Opus R128 tag gain by default: album gain for a catalogued album selection, track gain for other selections. `--normalize off|track|album` overrides this. `--bass DB` and `--treble DB` apply the tone controls; both default to zero for flat bypass. A future remote server handler can use the same PCM blocks, gain/headroom functions and tone controls to transmit processed audio to the client device; no server audio route exists yet. Driving the in-memory queue remains future work. More detailed equalization, spatial processing, and other optional effects remain later stages.
