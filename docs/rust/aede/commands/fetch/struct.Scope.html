    folders: Vec<String>,
    holds: Option<Held>,
}
Expand description

The folders typed after the command, and what the catalog holds under them.

A name and a folder narrow a run in two different ways — one asks who, the other asks where — and every pass has to honour both. Which artists, albums and tracks a folder holds is a walk over the catalog, so it is worked out once, here, exactly as the names are: six passes working it out separately is six chances for two of them to disagree about what ~/Music/Alastis means.

Default is the whole library, which is what the waiting counters ask for: they report what a pass would find over everything, not over what happened to be typed this time.

Fields§

§folders: Vec<String>

The folders, canonical, as the catalog spells them; empty for the whole library.

§holds: Option<Held>

What they hold. None when no folder was given, which is not the same as a folder that holds nothing — the first reaches everything, the second reaches nothing at all.

The scope the folders name, refusing one the catalog has never seen.

That refusal is super::scope_from’s, the same one check and playlist make and for the same reason: a folder added since the last scan would otherwise produce a run with nothing to do and a cheerful line saying so, which reads as there is nothing to fetch here and is in fact I have never heard of that folder.
