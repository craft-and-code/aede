1//! Wikipedia, reached through Wikidata: the prose MusicBrainz does not hold.
2//!
3//! MusicBrainz answers with identifiers, dates and relationships. It never
4//! answers with a sentence about the artist, because that is not what it is
5//! for. The sentence exists on Wikipedia — and the way from one to the other
6//! is the `wikidata` relationship MusicBrainz already returns.
7//!
8//! **Two requests, not one.** A Wikidata entity is the hub: it holds a
9//! *sitelink* per language, and a sitelink is a page title rather than a
10//! summary. So reaching a paragraph is
11//!
12//! ```text
13//! MusicBrainz artist  →  wikidata: .../wiki/Q11649
14//!                        Special:EntityData/Q11649.json   →  sitelinks.enwiki.title
15//!                        en.wikipedia.org/…/summary/<title>  →  extract
16//! ```
17//!
18//! That is why this is opt-in rather than part of every fetch: it doubles a
19//! run that already takes ten minutes over a large library, and the summary
20//! is the one fact here nobody needs in order to file their music.
21//!
22//! **Everything in this module is a decision, and none of it is a request.**
23//! The two URL builders and the two extractors below are pure functions over
24//! text and JSON, so what the program concludes from an answer is proven by
25//! the tests beside them, and only the handing of a URL to a client library is
26//! left unproven — the same split [`crate::musicbrainz`] follows.
27//!
28//! # The licence is not optional
29//!
30//! Wikipedia text is CC BY-SA. Reusing it obliges attribution, so the extract
31//! is only ever produced as a [`Prose`], which cannot hold the words without
32//! the page they came from and the terms they came under. There is deliberately
33//! no function here that returns a bare `String` of article text.
34

38/// The name this source is stored under in `sources.json`.
39///
40/// "wikipedia" rather than "wikidata": Wikidata is the road, the article is
41/// what a reader is being shown, and the credit has to name the article.
42pub const SOURCE: &str = "wikipedia";
43
44/// The licence Wikipedia article text is under.
45///
46/// Named as Wikimedia names it, because a credit that renames a licence is not
47/// a credit. Stored per record rather than assumed at display time: if this
48/// ever changes, records fetched before the change still say what they were
49/// taken under.
50pub const LICENCE: &str = "CC BY-SA 4.0";
51
52/// The name a portrait reached through Wikidata is stored under.
53///
54/// Not `wikipedia`, even though the same entity document is the source of
55/// both: an article's prose and an entity's `P18` image are two different
56/// claims, fetched to answer two different questions, and a record that
57/// carried both could not be re-fetched for one without silently dropping the
58/// other — `Sources::set` replaces a record whole, it does not merge fields
59/// into it. Keeping them as two records under two names is what lets
60/// `fetch --summaries` and `fetch --portraits` each redo their own work
61/// without undoing the other's.
62pub const PORTRAIT_SOURCE: &str = "wikidata";
63
64/// How long to leave between requests.
65///
66/// Wikimedia's limits are far looser than MusicBrainz's, but the polite rate
67/// is the one that never needs revisiting, and a run that is already paced at
68/// one per second gains nothing from going faster in one leg of it.
69pub const REQUEST_INTERVAL: std::time::Duration = std::time::Duration::from_millis(1100);

71/// Languages to look for an article in, best first.
72///
73/// English last rather than first would be the friendlier default and the
74/// wrong one: this list is a fallback chain, and the caller puts the reader's
75/// own language at its head. English is here as the floor, because for a great
76/// many artists it is the only article that exists.
77pub const FALLBACK_LANGS: [&str; 1] = ["en"];

79/// The Wikidata entity id inside a URL MusicBrainz returned.
80///
81/// MusicBrainz gives the relationship as a page URL rather than a bare id, and
82/// it does not always give the same one: `www.wikidata.org/wiki/Q11649` is the
83/// usual shape, but the entity URI `.../entity/Q11649` appears too. Both end
84/// in the id, so the id is read from the end rather than the middle.
85///
86/// Returns `None` for anything that does not end in an entity id, which is the
87/// honest answer for a link that leads somewhere else — a lexeme, a property,
88/// or a URL that was never Wikidata at all.
89pub fn entity_id(url: &str) -> Option<String> {
90    let last = url.trim_end_matches('/').rsplit('/').next()?;
91    // An entity id is `Q` and at least one digit, all digits. Checking the
92    // shape is what stops `.../wiki/Special:EntityData` or a property `P31`
93    // from being sent out as a lookup that cannot succeed.
94    let digits = last.strip_prefix('Q')?;
95    match !digits.is_empty() && digits.bytes().all(|b| b.is_ascii_digit()) {
96        true => Some(last.to_string()),
97        false => None,
98    }
99}

101/// Where to ask Wikidata about an entity.
102///
103/// `Special:EntityData` rather than the `wbgetentities` API: it is a plain
104/// document at a stable address, it needs no parameters to get wrong, and it
105/// is cached, which is the difference between being a polite client and being
106/// a load.
107pub fn entity_data_url(id: &str) -> String {
108    format!("https://www.wikidata.org/wiki/Special:EntityData/{id}.json")
109}

111/// The Commons filename in a Wikidata entity's `image` claim (`P18`), if it
112/// states one.
113///
114/// Mirrors the redirect handling [`article`] already does: the document may
115/// answer about a different id than the one asked for, and one entity in the
116/// document is no ambiguity about which that is — the same reasoning, applied
117/// to a claim instead of a sitelink.
118///
119/// `None` covers both an entity with no `P18` at all and one whose claim is
120/// there but not the ordinary "a filename" shape — a deprecated statement, a
121/// `novalue` — because a portrait fetch should not choke on either, only
122/// record that this entity had nothing usable.
123pub fn portrait_file(response: &Json, id: &str) -> Option<String> {
124    let entities = response.get("entities")?;
125    let entity = match entities.get(id) {
126        Some(entity) => entity,
127        None => only_value(entities)?,
128    };
129    entity
130        .get("claims")?
131        .get("P18")?
132        .as_arr()?
133        .first()?
134        .get("mainsnak")?
135        .get("datavalue")?
136        .get("value")?
137        .as_str()
138        .map(str::to_string)
139}

141/// Where to download a Commons file, at a given width.
142///
143/// `Special:FilePath` rather than resolving the MD5-sharded path Commons
144/// actually stores the file under: it is a stable redirect Commons maintains
145/// for exactly this, and following it costs one request, not a second API call
146/// to a different service to compute a hash Aède has no business working out
147/// itself.
148pub fn commons_file_url(filename: &str, width: u32) -> String {
149    format!(
150        "https://commons.wikimedia.org/wiki/Special:FilePath/{}?width={width}",
151        encode_title(filename)
152    )
153}

155/// An article on one language's Wikipedia.
156#[derive(Debug, Clone, PartialEq, Eq)]
157pub struct Article {
158    /// The language code — `en`, `fr` — which is also part of the address.
159    pub lang: String,
160    /// The page title, as Wikidata spells it, spaces and all.
161    pub title: String,
162}
163
164/// The article to read, from a `Special:EntityData` document.
165///
166/// `preferred` is tried in order, so a caller can ask for the reader's own
167/// language and fall back rather than choosing between "always English" and
168/// "nothing".
169///
170/// The document is keyed by entity id at the top, and an `EntityData` response
171/// may carry redirects — asking for `Q1` and being answered about `Q2` — so the
172/// id asked for is looked up first and, failing that, the single entity the
173/// document does carry is used. Guessing between several would be a coin toss,
174/// so several is `None`.
175pub fn article(response: &Json, id: &str, preferred: &[&str]) -> Option<Article> {
176    let entities = response.get("entities")?;
177    let entity = match entities.get(id) {
178        Some(entity) => entity,
179        // A redirect answers under the target's id. One entity means there is
180        // no ambiguity about which that is.
181        None => only_value(entities)?,
182    };
183    let sitelinks = entity.get("sitelinks")?;
184    for lang in preferred {
185        // Wikidata names the site, not the language: the English Wikipedia is
186        // `enwiki`, and `enwikiquote` or `enwikisource` are different projects
187        // that would answer with something other than an encyclopaedia entry.
188        let title = sitelinks
189            .get(&format!("{lang}wiki"))
190            .and_then(|s| s.field_str("title"))
191            .filter(|t| !t.trim().is_empty());
192        if let Some(title) = title {
193            return Some(Article {
194                lang: (*lang).to_string(),
195                title,
196            });
197        }
198    }
199    None
200}

202/// Where to ask for an article's opening paragraph.
203///
204/// The REST summary endpoint rather than the `action=query` API: it returns the
205/// lead paragraph already assembled and already plain text, where the older API
206/// returns wikitext or HTML that this program would then have to strip — and
207/// stripping markup to display it as fact is how a citation template ends up
208/// quoted at a user.
209pub fn summary_url(article: &Article) -> String {
210    format!(
211        "https://{}.wikipedia.org/api/rest_v1/page/summary/{}",
212        article.lang,
213        encode_title(&article.title)
214    )
215}

217/// A title as it goes into a REST path.
218///
219/// Spaces become underscores, as every Wikipedia address does, and everything
220/// outside the unreserved set is percent-encoded. Parentheses are encoded too:
221/// they are legal in a path, but article titles are full of them — `Marilyn
222/// Manson (band)` — and encoding them costs nothing while leaving them raw
223/// depends on every intermediary agreeing they are safe.
224fn encode_title(title: &str) -> String {
225    let mut out = String::with_capacity(title.len());
226    for byte in title.replace(' ', "_").bytes() {
227        match byte {
228            b'A'..=b'Z' | b'a'..=b'z' | b'0'..=b'9' | b'-' | b'_' | b'.' | b'~' => {
229                out.push(byte as char)
230            }
231            other => out.push_str(&format!("%{other:02X}")),
232        }
233    }
234    out
235}

237/// The paragraph, credited, from a REST summary document.
238///
239/// `None` when the page holds no extract — a disambiguation page, a redirect
240/// to one, a stub that is only an infobox — which is not an error: it is the
241/// same "asked, and there is nothing" the rest of the layer records.
242///
243/// The URL stored is the article's own canonical address when the response
244/// gives one, and the address that was asked otherwise. It is never left out:
245/// a `Prose` cannot be built without it, which is the point of the type.
246pub fn prose(response: &Json, asked: &Article) -> Option<Prose> {
247    let text = response
248        .field_str("extract")
249        .map(|t| t.trim().to_string())
250        .filter(|t| !t.is_empty())?;
251    // The canonical page URL sits under `content_urls.desktop.page`. It is
252    // preferred over the address that was asked because a title may have been
253    // followed through a redirect, and a credit has to point at the article a
254    // reader will actually find.
255    let canonical = response
256        .get("content_urls")
257        .and_then(|c| c.get("desktop"))
258        .and_then(|d| d.field_str("page"))
259        .filter(|u| !u.is_empty());
260    let lang = response
261        .field_str("lang")
262        .filter(|l| !l.is_empty())
263        .unwrap_or_else(|| asked.lang.clone());
264    Some(Prose {
265        text,
266        url: canonical.unwrap_or_else(|| article_url(asked)),
267        lang,
268        licence: LICENCE.to_string(),
269    })
270}

272/// A readable address for an article, for when the response gives none.
273fn article_url(article: &Article) -> String {
274    format!(
275        "https://{}.wikipedia.org/wiki/{}",
276        article.lang,
277        encode_title(&article.title)
278    )
279}

281/// The only value in an object, when there is exactly one.
282fn only_value(value: &Json) -> Option<&Json> {
283    match value {
284        Json::Obj(fields) if fields.len() == 1 => fields.values().next(),
285        _ => None,
286    }
