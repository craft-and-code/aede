1//! What other sources say about the library.
2//!
3//! The catalog holds what the files say. [`crate::user`] holds what the user
4//! says. This holds what somebody else says — MusicBrainz first, a plugin
5//! later — and it is a third store rather than a column in either of the other
6//! two, for reasons written out in `docs/design/attribution.md`.
7//!
8//! The rule the whole module exists to enforce: **a fetched value sits beside
9//! the tag, never on top of it.** Writing a fetched genre into the catalog's
10//! `genre` would cost three things at once — saying where the value came from,
11//! noticing that the source and the tag differ, and undoing it — and it would
12//! not even survive, because a scan rebuilds the catalog from the files.
13//!
14//! Nothing here touches the network. This is the receptacle; filling it from
15//! MusicBrainz is a later step, and the layer is testable without a single
16//! request.

39/// How the record was attached to the entity it describes.
40///
41/// Kept because the roadmap's rule for M1 is that a file matched to a release
42/// approximately is never treated as certain. A value reached by asking for a
43/// known identifier and a value reached by guessing from a name are different
44/// claims, and a layer that stored them identically could not offer the
45/// review that makes an approximate match acceptable in the first place.
46#[derive(Debug, Clone, Copy, PartialEq, Eq)]
47pub enum Confidence {
48    /// The source was asked about this exact thing, by identifier.
49    Identified,
50    /// Reached by matching names and metadata, scored from 0 to 100.
51    Matched(u8),
52}
53
54impl Confidence {
55    /// A matched confidence, with the score bounded to 0–100.
56    ///
57    /// Bounded here rather than trusted from the caller: a score above 100
58    /// would print as one and sort above a certainty, which is exactly the
59    /// confusion this type exists to prevent.
60    pub fn matched(score: u8) -> Confidence {
61        Confidence::Matched(score.min(100))
62    }
63
64    /// `true` when the record was reached by identifier rather than by guess.
65    pub fn is_certain(self) -> bool {
66        matches!(self, Confidence::Identified)
67    }
68}

70/// A user's explicit decision about one external identity claim.
71///
72/// This is deliberately separate from [`Confidence`]. Confidence says how a
73/// service found the candidate; a review says whether the library owner chose
74/// to trust that candidate. Accepting a 92% name match must not rewrite history
75/// and pretend it was an identifier lookup, while rejecting an exact lookup
76/// that conflicts with a local tag must remain possible too.
77#[derive(Debug, Clone, Copy, PartialEq, Eq)]
78pub enum ReviewDecision {
79    /// The source claim may participate in graph traversal.
80    Accepted,
81    /// The source claim remains visible evidence but must not become a link.
82    Rejected,
83}

146/// A piece of prose taken from somewhere, with what its licence obliges.
147///
148/// **One value, not four fields.** Wikipedia is CC BY-SA: the text may be
149/// reused, and attribution has to travel with it. A `text` field beside a
150/// separate optional `url` would make it possible — and therefore eventually
151/// certain — to hold the words without the credit: one code path that fills
152/// the first and forgets the second, one export that copies one and not the
153/// other, and the project is quietly out of compliance.
154///
155/// So they are the same value. There is no way to store the sentence without
156/// storing where it came from, in which language, and under what terms,
157/// because the type does not offer one.
158#[derive(Debug, Clone, PartialEq, Eq)]
159pub struct Prose {
160    /// The words themselves.
161    pub text: String,
162    /// The page they came from, which is the attribution a reader can follow.
163    pub url: String,
164    /// Language code of that page, so a reader knows what they are getting.
165    pub lang: String,
166    /// The licence, named as the source names it — `CC BY-SA 4.0`.
167    ///
168    /// **Stored per record, not looked up from a constant.** It is the same
169    /// string for every Wikipedia article today, so carrying a copy on each row
170    /// looks like waste — about twenty-four bytes, ten kilobytes over a large
171    /// library. It buys two things that a constant read at display time cannot.
172    ///
173    /// It is a **fact about the fetch**, like [`SourceRecord::fetched_at`]: it
174    /// says what these words were taken under, not what the current build
175    /// believes they would be taken under now. Wikimedia has already moved once
176    /// — CC BY-SA 3.0 to 4.0 — and with a constant that upgrade silently
177    /// relabels every paragraph fetched before it.
178    ///
179    /// And `Prose` is not Wikipedia's. It is prose with its terms, so the next
180    /// source of a biography — a plugin, a label, a discography site under
181    /// quite different terms — files it in this same field, and the record says
182    /// which. Moving the licence out to the source that usually supplies it
183    /// would make the second source a special case of the first.
184    pub licence: String,
185}
186
187impl Prose {
188    /// The line that has to appear wherever the text does.
189    ///
190    /// The **language is named**, and that is not decoration. This text is
191    /// fetched in one language and kept in one language, so a reader who wanted
192    /// French and is reading English has no way to tell whether their
193    /// preference was ignored, whether the article does not exist in French, or
194    /// whether the prose was fetched before they expressed a preference at all.
195    /// The field was stored from the first version and displayed nowhere — the
196    /// same dead end `source_id` and the fingerprints had. Now the screen says
197    /// which language it is, and the way to ask for another is one line below.
198    pub fn credit(&self) -> String {
199        format!("{} — in {} — {}", self.url, self.lang, self.licence)
200    }
201}

217/// What a source says about one artist.
218///
219/// Every field is optional: a source may not hold it, and an empty answer is
220/// not an error. None of these have a tag counterpart — there is no widely
221/// used tag for an artist's country — so this is knowledge the files simply
222/// do not carry, rather than a second opinion about something they do.
223#[derive(Debug, Clone, Default, PartialEq, Eq)]
224pub struct ArtistFacts {
225    /// Country or area of origin, as the source names it.
226    pub area: Option<String>,
227    /// The same country as a two-letter code, when the source gives one.
228    ///
229    /// Kept **beside** the name rather than instead of it, because the source
230    /// states both and they answer different needs: `area` is what a reader
231    /// sees, the code is what they can type. It used to be read only as a
232    /// fallback for a missing name and otherwise dropped — a fact the source
233    /// had stated, thrown away because another field happened to be filled.
234    ///
235    /// ISO 3166-1 alpha-2, so the United Kingdom is `GB` and not `UK`.
236    pub country_code: Option<String>,
237    /// Formation date: a year, or a fuller date when the source has one.
238    pub began: Option<String>,
239    /// When it ended, for a group that has.
240    pub ended: Option<String>,
241    /// Whether it is still going, when the source says so.
242    ///
243    /// Distinct from [`ArtistFacts::ended`] being absent, and the distinction
244    /// is the whole point: a band with no end date may be one that never
245    /// stopped, or one nobody has filled in. `Some(true)` is an answer,
246    /// `None` is a silence, and a reader shown the same thing for both learns
247    /// nothing.
248    pub active: Option<bool>,
249    /// `person`, `group`, `orchestra`, `choir`… as the source classifies it.
250    pub kind: Option<String>,
251    /// The short phrase a source uses to tell two same-named artists apart —
252    /// "US industrial metal band", "UK folk singer", and sometimes something
253    /// as unhelpful as "the band".
254    ///
255    /// **Not a description**, and it must not be labelled as one: it exists to
256    /// separate two entries that share a name, so it is written against
257    /// whatever the other entry is. Shown as a note for that reason.
258    pub disambiguation: Option<String>,
259    /// Genres, as the source's editors voted them, most agreed first.
260    ///
261    /// Beside the genre tag rather than over it: what a crowd calls a record
262    /// and what its tags call it are two answers, and the second is the one
263    /// the user chose to write.
264    pub genres: Vec<String>,
265    /// Other names the same artist is known by.
266    pub aliases: Vec<String>,
267    /// Wikidata entity page, when the source links to one.
268    ///
269    /// The one link that leads somewhere else: Wikidata is how a real article
270    /// is reached in the reader's own language, so it is stored under its own
271    /// name rather than lost in a list of URLs.
272    pub wikidata: Option<String>,
273    /// Discogs page, when the source links to one.
274    pub discogs: Option<String>,
275    /// The artist's own site, when they have one the source knows about.
276    pub homepage: Option<String>,
277    /// A few sentences about the artist, with the attribution its licence
278    /// requires — see [`Prose`].
279    ///
280    /// MusicBrainz never fills this: it holds identifiers and relationships,
281    /// not prose. It comes from an encyclopaedia, and it is stored as one
282    /// inseparable value for the reason written on the type.
283    pub summary: Option<Prose>,
284    /// Every record the source credits to this artist — see [`KnownRelease`].
285    ///
286    /// **On the artist, and deliberately not on the releases.** A release key
287    /// is `artist|title|folder`, and an album you do not own has no folder, so
288    /// a record you are missing cannot be an entity of this layer at all. It is
289    /// instead a fact *about the artist*: "MusicBrainz credits fourteen albums
290    /// to this name".
291    ///
292    /// Which of them are missing from the shelf is then **derived on read**, by
293    /// comparing that list with the catalog — the same rule the whole layer
294    /// follows for agreement with a tag. Storing "missing" would go stale the
295    /// moment the album is bought, and the catalog would hold a claim it had
296    /// stopped being able to justify.
297    pub discography: Vec<KnownRelease>,
298    /// When a complete discography browse succeeded, including an empty answer.
299    ///
300    /// Unix seconds, set only after every page was received and validated.
301    /// Absent on older documents and artist lookups that never browsed release
302    /// groups. A legacy nonempty list remains reusable without this optional
303    /// field; an empty list needs it to distinguish an answer from no request.
304    /// An artist lookup must preserve it only while the artist ID stays the same.
305    pub discography_fetched_at: Option<u64>,
306    /// Who played in this band, or which bands this person played in — see
307    /// [`Membership`].
308    ///
309    /// One list, not two, because MusicBrainz states **one** relation and the
310    /// two readings are the same fact seen from either end. Splitting it here
311    /// would mean deciding at write time which question a reader was going to
312    /// ask, and getting it wrong for a person who is both — a soloist with a
313    /// backing band under their own name is exactly that.
314    pub members: Vec<Membership>,
315    /// A picture of the artist, when a source holds an address for one — see
316    /// [`Picture`].
317    ///
318    /// The address, never the bytes. The image itself is written to disk —
319    /// beside the music when one folder holds every album of theirs, an
320    /// `assets/` folder otherwise — and rediscovered from there, the same way
321    /// `cover.jpg` is never registered anywhere either. What is kept here is
322    /// only the fact that a source was asked and what it answered, so a later
323    /// run does not ask again for nothing: see `fetch --portraits`.
324    pub portrait: Option<Picture>,
325    /// The artist's logo, when a source holds an address for one — see
326    /// [`Picture`].
327    ///
328    /// Same shape and same reason as [`ArtistFacts::portrait`]: the address
329    /// only, written to disk and rediscovered from there, kept here so a
330    /// later run does not ask again for nothing: see `fetch --logos`.
331    pub logo: Option<Picture>,
332}

342    /// The line-up: everyone the source says played in **this** artist.
343    pub fn line_up(&self) -> impl Iterator<Item = &Membership> {
344        self.members.iter().filter(|m| m.side == Side::Player)
345    }
346
347    /// The other way round: the bands **this** artist played in.
348    pub fn bands(&self) -> impl Iterator<Item = &Membership> {
349        self.members.iter().filter(|m| m.side == Side::Group)
350    }

352    /// Who the source places in this band in a given year, and how many
353    /// members it cannot place at all.
354    ///
355    /// **This is the whole reason the dates are worth fetching**: a line-up is
356    /// a fact about an artist, an album is a fact about a year, and crossing
357    /// them answers the question a listener actually asks — who was in the band
358    /// when this record came out.
359    ///
360    /// Derived when read, never stored. A stored line-up would be a claim the
361    /// catalog had stopped being able to justify the moment either side
362    /// changed, and it is the same rule the missing-albums list already
363    /// follows.
364    ///
365    /// A row is placed only when the source's own dates put it there: an
366    /// undated membership, or one the source says has ended without saying
367    /// when, is **counted rather than shown**. Including it would put a
368    /// musician on a record they may not be on, which is the one mistake here
369    /// that matters; dropping it in silence would be a filter the reader
370    /// cannot see.
371    pub fn line_up_in(&self, year: u32) -> (Vec<&Membership>, usize) {
372        let mut placed = Vec::new();
373        let mut undated = 0;
374        for member in self.line_up() {
375            match member.covers(year) {
376                Some(true) => placed.push(member),
377                Some(false) => {}
378                None => undated += 1,
379            }
380        }
381        (placed, undated)
382    }
383}

385/// Which end of a membership the named artist is.
386///
387/// A membership is one relation between two artists, and MusicBrainz returns
388/// it on both of them with a direction. Losing that direction is not a cosmetic
389/// mistake: it puts Judas Priest in the list of Ozzy Osbourne's members.
390#[derive(Debug, Clone, Copy, PartialEq, Eq)]
391pub enum Side {
392    /// The named artist played **in** the artist this record describes, which
393    /// therefore is a band.
394    Player,
395    /// The named artist **is** the band, and the artist this record describes
396    /// played in it.
397    Group,
398}

400/// One spell in a band, as a source dates it.
401///
402/// **A person can appear twice**, and the second row is not a duplicate: Ozzy
403/// Osbourne was in Black Sabbath from 1968 to 1979 and again from 1997, and a
404/// list that folded the two into one span would claim he was there in 1985.
405/// MusicBrainz states them as two relations and they are kept as two rows.
406#[derive(Debug, Clone, PartialEq, Eq)]
407pub struct Membership {
408    /// MusicBrainz relationship row identifier, when exposed.
409    pub relation_id: Option<String>,
410    /// Stable MusicBrainz relationship type identifier.
411    pub role_id: Option<String>,
412    /// Direction exactly as returned by MusicBrainz.
413    pub direction: Option<String>,
414    /// The other artist's MusicBrainz identifier, which is what makes a later
415    /// fetch about them an update rather than a second opinion.
416    pub mbid: String,
417    /// The other artist's name, as the source spells it.
418    pub name: String,
419    /// Exact spelling used for the related artist in this relationship.
420    pub credited_as: Option<String>,
421    /// Which end of the relation that name is — see [`Side`].
422    pub side: Side,
423    /// How the source names the relationship, in its own words: `member of
424    /// band`, `instrumental supporting musician`.
425    ///
426    /// Kept verbatim and shown verbatim, the same rule
427    /// [`KnownRelease::stated_type`] follows. The two are not the same fact — a
428    /// founding member and a guitarist hired for one tour are both on a record
429    /// and only one of them was in the band — and paraphrasing them into one
430    /// word would throw away the distinction MusicBrainz took the trouble to
431    /// draw.
432    pub kind: String,
433    /// What the source lists against the relationship.
434    ///
435    /// **Not "instruments", although most of them are.** Measured on a real
436    /// answer: Judas Priest's line-up carries `["guitar family", "original"]`
437    /// on one row, where `original` marks an original member and is not an
438    /// instrument at all. Calling this field `instruments` would put a lie in
439    /// a column header, so it carries the source's own word and its own
440    /// values.
441    pub attributes: Vec<String>,
442    /// When it started: a year, or a fuller date when the source has one.
443    pub began: Option<String>,
444    /// When it stopped.
445    pub ended: Option<String>,
446    /// Whether the source says it is over.
447    ///
448    /// The same distinction [`ArtistFacts::active`] draws, and it matters more
449    /// here: a membership with no end date may be a current one or one nobody
450    /// has filled in, and printing "1968–" for both tells the reader something
451    /// the source never said. `Some(false)` is "still in the band".
452    pub over: Option<bool>,
453}
454
455impl Membership {
456    /// Whether this membership was running in a given year: `Some(true)`,
457    /// `Some(false)`, or `None` where the source's dates cannot say.
458    ///
459    /// The three-way answer is the point. A membership with no start date
460    /// places nobody, and one the source says has **ended without saying
461    /// when** places nobody either — the end is somewhere, and "somewhere"
462    /// cannot be compared with a year. Both come back `None`, so a caller has
463    /// to decide what to do about them rather than being handed a `false` that
464    /// looks like knowledge.
465    pub fn covers(&self, year: u32) -> Option<bool> {
466        let started = self.year(self.began.as_deref())?;
467        if started > year {
468            return Some(false);
469        }
470        match (self.year(self.ended.as_deref()), self.over) {
471            (Some(stopped), _) => Some(stopped >= year),
472            // Still in the band, said so by the source.
473            (None, Some(false)) => Some(true),
474            // Over, with no date for it, or nothing said at all.
475            (None, _) => None,
476        }
477    }
478
479    /// The year out of a MusicBrainz date, which is `1968` or `1968-02-13`.
480    fn year(&self, date: Option<&str>) -> Option<u32> {
481        date?.get(..4)?.parse().ok()
482    }
483
484    /// The years as a reader recognises them: `1968–1979`, `1968–` for a
485    /// current member, `1968` where the source only knows a start and does not
486    /// say whether it ended.
487    ///
488    /// **Never invents an end.** A dash trailing into nothing is a claim that
489    /// the membership is still going, and it is one MusicBrainz makes with
490    /// `ended: false` rather than with a missing date.
491    pub fn years(&self) -> String {
492        let began = self.began.as_deref().unwrap_or("");
493        match (&self.ended, self.over) {
494            (Some(end), _) => format!("{began}–{end}"),
495            (None, Some(false)) => format!("{began}–"),
496            // Said to be over, with no date for it: the reader is told that
497            // much rather than being shown an open range that would be wrong.
498            (None, Some(true)) => format!("{began}–?"),
499            (None, None) => began.to_string(),
500        }
501    }
502}

504/// One record a source credits to an artist, whether or not you own it.
505///
506/// Enough to recognise it and to show it: the identifier that makes a second
507/// fetch an update, the title, when it first appeared, and what kind of record
508/// it is. Not a [`ReleaseFacts`], which is what a source says about an album
509/// *in the catalog* — this is a name on a list, and the difference matters:
510/// one is attached to files, the other is precisely the one that is not.
511#[derive(Debug, Clone, PartialEq, Eq)]
512pub struct KnownRelease {
513    /// Release-group identifier, which is what the catalog's own
514    /// `release_group_mbid` can be compared against without guessing.
515    pub mbid: String,
516    /// Title as the source spells it.
517    pub title: String,
518    /// When the album first appeared — the year a reader recognises it by.
519    pub first_released: Option<String>,
520    /// Album, Single, EP, Broadcast, Other.
521    pub primary_type: Option<String>,
522    /// Compilation, Soundtrack, Live, Remix, Demo…
523    pub secondary_types: Vec<String>,
524}
525
526impl KnownRelease {
527    /// `true` for a studio album: primary type Album, and nothing else.
528    ///
529    /// The filter that makes a completeness report readable rather than a wall.
530    /// A discography holds every single, every live recording, every
531    /// compilation somebody assembled, and reporting all of them as *missing*
532    /// would be true and useless — nobody's shelf holds every single ever
533    /// pressed, and a report that is mostly noise is a report nobody opens.
534    ///
535    /// Applied here, on what came back, rather than trusted to the request: a
536    /// server-side filter narrows what travels, but only this decides what is
537    /// shown, so a parameter the service ignores costs bandwidth and not
538    /// correctness.
539    pub fn is_studio_album(&self) -> bool {
540        self.primary_type.as_deref() == Some("Album") && self.secondary_types.is_empty()
541    }
542
543    /// What the source calls this record, in the source's own words.
544    ///
545    /// For a report that has left something out to be able to say **why**. The
546    /// words are MusicBrainz's — `Album · Live`, `Single`, `Album · Compilation`
547    /// — rather than a vocabulary of our own, because the reader's next move is
548    /// often to go and correct the type on the page where it is set, and a
549    /// paraphrase would send them looking for a word that is not written there.
550    ///
551    /// A record nobody has typed at all says so: it is not a studio album
552    /// either, and having no type is exactly why it was left out.
553    pub fn stated_type(&self) -> String {
554        let mut parts: Vec<&str> = Vec::new();
555        if let Some(primary) = &self.primary_type {
556            parts.push(primary);
557        }
558        parts.extend(self.secondary_types.iter().map(String::as_str));
559        match parts.is_empty() {
560            true => "no type".to_string(),
561            false => parts.join(" · "),
562        }
563    }
564
565    /// The year, for a date that may be a year, a month or a full date.
566    pub fn year(&self) -> Option<&str> {
567        self.first_released.as_deref().map(|d| &d[..4.min(d.len())])
568    }
569}

573/// Unlike the artist fields, these do have tag counterparts — Picard writes
574/// `RELEASETYPE`, `DATE` and `LABEL` — which is what makes a release the place
575/// where agreement and disagreement can actually be observed.
576#[derive(Debug, Clone, Default, PartialEq, Eq)]
577pub struct ReleaseFacts {
578    /// Album, Single, EP, Broadcast, Other — the release group's primary type.
579    pub primary_type: Option<String>,
580    /// Compilation, Soundtrack, Live, Remix, Demo… any number of them.
581    pub secondary_types: Vec<String>,
582    /// First release date of the group, which is not the date of this edition:
583    /// a 2011 remaster of a 1973 album was first released in 1973.
584    pub first_released: Option<String>,
585    /// Label, as the source names it.
586    pub label: Option<String>,
587    /// The label's own MusicBrainz identifier, when the same answer carried
588    /// one.
589    ///
590    /// Kept beside the name rather than instead of it, the same choice
591    /// [`ArtistFacts::country_code`] makes beside [`ArtistFacts::area`]: the
592    /// source states both, and a reader who only wants to see the label reads
593    /// the name, while `fetch --labels` reads the identifier. Read from the
594    /// very `label-info` entry the name came from — never from a different
595    /// one — so a release crediting several labels is never misattributed.
596    /// Never from a tag: no widely used tag carries a label's MusicBrainz
597    /// identifier, so this can only ever come from a release lookup, unlike
598    /// every other `mbid` in [`crate::model`].
599    pub label_mbid: Option<String>,
600    /// Address of the front image, when a source holds one.
601    ///
602    /// The address rather than the picture: a catalog is a description of a
603    /// library, and megabytes of artwork inside `sources.json` would make every
604    /// load of it slower for something that belongs beside the music. The image
605    /// is written into the album's folder, where the next scan discovers it
606    /// exactly as it would one the user put there.
607    ///
608    /// Kept so that "asked, and there is a cover" can be told from "asked, and
609    /// there is none" — the distinction this whole layer exists for — and so
610    /// that a second run costs nothing.
611    pub cover_art: Option<String>,
612    /// Exact edition queried for these relationships, absent for a group search.
613    pub edition_mbid: Option<String>,
614    /// Artist relationships on this edition, never on the release group.
615    pub credits: Vec<CreditLink>,
616    /// Distinguishes an empty lookup from an edition never queried for credits.
617    pub relationships_complete: bool,
618}

620/// What a source says, for one kind of entity.
621///
622/// An enum rather than a flat bag of `(field, value)` strings: the display,
623/// the query grammar and `doctor` all have to know what a field *means*, and a
624/// generic bag pushes that knowledge into string literals scattered through
625/// the program. [`crate::analysis::FileAnalysis`] made the same choice.
626///
627/// # The two variants are not the same size, on purpose
628///
629/// An artist carries twelve fields, one of them a paragraph; a release carries
630/// four. Clippy points out that a `Facts` is therefore as large as its larger
631/// variant, and the usual remedy is to box that one. It is the wrong remedy
632/// here: artist records are the majority of this layer, so boxing them puts a
633/// heap allocation and a pointer chase on the common path in order to shrink
634/// the rare one. The whole store is a few hundred rows of a few hundred bytes
635/// — under a hundred kilobytes — and it is read once at start-up.
636#[allow(clippy::large_enum_variant)]
637#[derive(Debug, Clone, PartialEq, Eq)]
638pub enum Facts {
639    /// About an artist.
640    Artist(ArtistFacts),
641    /// About a release.
642    Release(ReleaseFacts),
643    /// About one recorded performance, identified by its sound.
644    Track(TrackFacts),
645    /// About a record label, including attributed prose when available.
646    Label(LabelFacts),
647}
648
649impl Facts {
650    /// The kind of entity these facts can describe.
651    ///
652    /// This is what makes a record's entity kind and its contents impossible
653    /// to contradict each other: the kind is derived from the facts rather
654    /// than stored beside them.
655    pub fn kind(&self) -> EntityKind {
656        match self {
657            Facts::Artist(_) => EntityKind::Artist,
658            Facts::Release(_) => EntityKind::Release,
659            Facts::Track(_) => EntityKind::Track,
660            Facts::Label(_) => EntityKind::Label,
661        }
662    }
663
664    /// `true` when the source answered but said nothing at all.
665    ///
666    /// Distinct from having no record: "asked, and it holds nothing about
667    /// this" and "never asked" are two different states, and the whole layer
668    /// exists to keep them apart.
669    pub fn is_empty(&self) -> bool {
670        match self {
671            Facts::Artist(a) => a == &ArtistFacts::default(),
672            Facts::Release(r) => r == &ReleaseFacts::default(),
673            Facts::Track(t) => t == &TrackFacts::default(),
674            Facts::Label(l) => l == &LabelFacts::default(),
675        }
676    }
677}

1092/// Everything other sources have said, as it sits in `sources.json`.
1093#[derive(Debug, Clone, Default, PartialEq, Eq)]
1094pub struct Sources {
1095    /// One row per entity and source.
1096    pub records: Vec<SourceRecord>,
1097    /// Explicit answers to claims that could not safely resolve themselves.
1098    pub reviews: Vec<SourceReview>,
1099    /// User decisions about individual source credits.
1100    pub credit_exclusions: Vec<CreditExclusion>,
1101}
1102
1103impl Sources {
1104    /// What one source says about one entity, if it has said anything.
1105    pub fn get(&self, entity: &EntityRef, source: &str) -> Option<&SourceRecord> {
1106        self.records
1107            .iter()
1108            .find(|r| r.source == source && r.key == entity.key && r.facts.kind() == entity.kind)
1109    }
1110
1111    /// Everything every source says about one entity.
1112    ///
1113    /// Several rows are the point rather than a defect: two sources that
1114    /// disagree are two rows, and the disagreement is reported instead of
1115    /// being resolved behind the user's back.
1116    pub fn about<'a>(&'a self, entity: &'a EntityRef) -> impl Iterator<Item = &'a SourceRecord> {
1117        self.records
1118            .iter()
1119            .filter(move |r| r.key == entity.key && r.facts.kind() == entity.kind)
1120    }
1121
1122    /// The current decision for this exact source claim.
1123    pub fn review_for(&self, record: &SourceRecord) -> Option<&SourceReview> {
1124        let entity = record.entity();
1125        self.reviews.iter().find(|review| {
1126            review.entity == entity
1127                && review.source == record.source
1128                && review.source_id == record.source_id
1129        })
1130    }
1131
1132    /// Whether a source record is safe to use as a graph relationship.
1133    ///
1134    /// A decision wins over the mechanical confidence. With no decision, only
1135    /// exact attachments that do not contradict a local MusicBrainz identity
1136    /// are trusted.
1137    pub fn is_trusted(&self, catalog: &crate::model::Catalog, record: &SourceRecord) -> bool {
1138        if let Some(review) = self.review_for(record) {
1139            return trusted_with_identity(record, None, Some(review.decision));
1140        }
1141        let local_id = if record.source == MUSICBRAINZ && record.confidence.is_certain() {
1142            local_musicbrainz_id(catalog, &record.entity())
1143        } else {
1144            None
1145        };
1146        trusted_with_identity(record, local_id.as_deref(), None)
1147    }
1148
1149    /// Trust a track claim whose canonical recording is already resolved.
1150    /// Reusing that endpoint avoids searching every local path for each claim.
1151    pub(crate) fn is_trusted_recording(
1152        &self,
1153        catalog: &crate::model::Catalog,
1154        record: &SourceRecord,
1155        recording_id: Id,
1156    ) -> bool {
1157        if let Some(review) = self.review_for(record) {
1158            return trusted_with_identity(record, None, Some(review.decision));
1159        }
1160        let local_id = catalog
1161            .recording(recording_id)
1162            .and_then(|recording| recording.mbid.as_deref());
1163        trusted_with_identity(record, local_id, None)
1164    }
1165
1166    /// Every current claim requiring or carrying an explicit review.
1167    pub fn review_items(&self, catalog: &crate::model::Catalog) -> Vec<ReviewItem> {
1168        let mut items = Vec::new();
1169        for record in &self.records {
1170            let review = self.review_for(record);
1171            let reason = match record.confidence {
1172                Confidence::Matched(score) => ReviewReason::Approximate { score },
1173                Confidence::Identified => match identity_conflict(catalog, record) {
1174                    Some((local_id, sourced_id)) => ReviewReason::IdentityConflict {
1175                        local_id,
1176                        sourced_id,
1177                    },
1178                    None if review.is_some() => ReviewReason::PriorDecision,
1179                    None => continue,
1180                },
1181            };
1182            items.push(ReviewItem {
1183                id: review_id(record),

1290            }
1291            None => {

1293                false
1294            }
1295        }

1617    /// Reconciles one label's explicit tag identity with its source record.
1618    pub fn label_identity(
1619        &self,
1620        catalog: &crate::model::Catalog,
1621        label_id: Id,
1622    ) -> Option<LabelIdentityResolution> {
1623        let label = catalog.label(label_id)?;
1624        let entity = EntityRef::of(catalog, EntityKind::Label, label_id)?;
1625        let source = self.get(&entity, MUSICBRAINZ);
1626        let local = label
1627            .mbid
1628            .as_deref()
1629            .map(str::trim)
1630            .filter(|id| !id.is_empty());
1631        let Some(record) = source else {
1632            return local.map(|mbid| LabelIdentityResolution::Local {
1633                mbid: mbid.to_string(),
1634            });
1635        };
1636        let sourced = record
1637            .source_id
1638            .as_deref()
1639            .map(str::trim)
1640            .filter(|id| !id.is_empty());
1641        let Some(sourced) = sourced else {
1642            return local.map(|mbid| LabelIdentityResolution::Local {
1643                mbid: mbid.to_string(),
1644            });
1645        };
1646
1647        if let Some(review) = self.review_for(record) {
1648            return Some(match review.decision {
1649                ReviewDecision::Accepted => LabelIdentityResolution::Accepted {
1650                    mbid: sourced.to_string(),
1651                    local_mbid: local.map(str::to_string),
1652                    source: record.source.clone(),
1653                    fetched_at: record.fetched_at,
1654                    reviewed_at: review.reviewed_at,
1655                },
1656                ReviewDecision::Rejected => LabelIdentityResolution::Rejected {
1657                    local_mbid: local.map(str::to_string),
1658                    sourced_mbid: sourced.to_string(),
1659                    source: record.source.clone(),
1660                    reviewed_at: review.reviewed_at,
1661                },
1662            });
1663        }
1664
1665        if !record.confidence.is_certain() {
1666            return Some(LabelIdentityResolution::Suggested {
1667                mbid: sourced.to_string(),
1668                source: record.source.clone(),
1669                confidence: record.confidence,
1670                fetched_at: record.fetched_at,
1671            });
1672        }
1673        match local {
1674            None => Some(LabelIdentityResolution::Confirmed {
1675                mbid: sourced.to_string(),
1676                source: record.source.clone(),
1677                fetched_at: record.fetched_at,
1678            }),
1679            Some(local) if local == sourced => Some(LabelIdentityResolution::Agrees {
1680                mbid: local.to_string(),
1681                source: record.source.clone(),
1682                fetched_at: record.fetched_at,
1683            }),
1684            Some(local) => Some(LabelIdentityResolution::Conflict {
1685                local_mbid: local.to_string(),
1686                sourced_mbid: sourced.to_string(),
1687                source: record.source.clone(),
1688                fetched_at: record.fetched_at,
1689            }),
1690        }
1691    }

1818fn review_id(record: &SourceRecord) -> String {
1819    // FNV-1a is used only as a stable compact selector, never as identity or
1820    // security. The command still rejects an ambiguous prefix.
1821    let mut hash = 0xcbf29ce484222325u64;
1822    for part in [
1823        record.facts.kind().as_str(),
1824        record.key.as_str(),

1870/// Counts what this catalog can currently place.
1871///
1872/// Nothing is rewritten here, and that is the difference with
1873/// [`crate::user::reconcile`]. Annotations are reattached in place because a
1874/// note whose file moved is **lost** otherwise, so it is worth guessing from a
1875/// name and a size when exactly one file matches.
1876///
1877/// A fetched value is not in that position: it is re-fetchable. A release key
1878/// carries the folder the album sits in, so moving an album does break the
1879/// attachment — and the right answer there is to ask the source again, not to
1880/// guess. Guessing would risk filing what MusicBrainz said about one album
1881/// onto another to save a network call, which is a poor trade in a layer whose
1882/// whole promise is that every value can be traced to what it describes.
1883///
1884/// So a record that does not resolve simply waits, exactly as an imported
1885/// analysis waits for the file it describes to be scanned.
1886pub fn attachment(sources: &Sources, catalog: &crate::model::Catalog) -> Attachment {
1887    let mut report = Attachment::default();
1888    for record in &sources.records {
1889        match record.entity().resolve(catalog).is_some() {
1890            true => report.attached += 1,
1891            false => report.waiting += 1,
1892        }
1893    }
1894    report
1895}

1901/// What a source's value amounts to, next to the tag it can be compared with.
1902///
1903/// **Derived on read, never stored.** A stored "agrees" goes stale the moment
1904/// the file is re-tagged, and the catalog would then hold a claim it has
1905/// stopped being able to justify. What is stored is the answer itself, whole;
1906/// this is computed from it. That is also what makes "does my tag still
1907/// match?" an offline question.
1908#[derive(Debug, Clone, PartialEq, Eq)]
1909pub enum Verdict {
1910    /// The source and the tag say the same thing.
1911    Agrees,
1912    /// They do not, and both are named so the reader can judge.
1913    Differs {
1914        /// What the source says.
1915        theirs: String,
1916        /// What the tag says.
1917        yours: String,
1918    },
1919    /// There is no tag to compare against, so the source adds rather than
1920    /// contradicts.
1921    NothingToCompare,
1922}
1923
1924/// Compares what a source says with what the tags say.
1925///
1926/// The comparison goes through [`crate::text::normalize`], the same
1927/// normalisation the catalog uses to decide that two spellings are one name —
1928/// case, diacritics, punctuation and a leading article. `Album` and `album`,
1929/// `Björk` and `Bjork`, `The Beatles` and `Beatles, The` are agreement, and
1930/// reporting them as disagreement would train the reader to skip the report.
1931///
1932/// What it does **not** fold is worth stating, because it is the case that
1933/// will produce the first false alarm: `&` and `and` are different words to
1934/// `normalize`, so `Rock & Roll` against `Rock and Roll` is reported as a
1935/// difference. Widening the normalisation is the wrong fix — it is the
1936/// catalog's identity function, and loosening it there to quiet a report here
1937/// would start merging artists. If the noise becomes real, the answer is a
1938/// comparison of its own, not a change to what counts as one name.
1939pub fn verdict(theirs: &str, yours: Option<&str>) -> Verdict {
1940    let Some(yours) = yours.map(str::trim).filter(|y| !y.is_empty()) else {
1941        return Verdict::NothingToCompare;
1942    };
1943    match crate::text::normalize(theirs) == crate::text::normalize(yours) {
1944        true => Verdict::Agrees,
1945        false => Verdict::Differs {
1946            theirs: theirs.trim().to_string(),
1947            yours: yours.to_string(),
1948        },
1949    }
1950}
1951
1952/// The verdict for a field that holds a **set**, not a value: genres.
1953///
1954/// Comparing sets as strings is what produced the first false alarm of this
1955/// layer: MusicBrainz said `pop, dance-pop, electropop, europop`, the files said
1956/// `Rock, Pop`, and the report called that a disagreement. It is not. The tags
1957/// say the record is pop *and* rock; MusicBrainz says pop and three finer words
1958/// for it. Nobody is contradicting anybody.
1959///
1960/// So the rule is **overlap, not equality**. Genres are not exclusive and the
1961/// two sides are not even trying to answer with the same granularity — one is
1962/// what a crowd voted, the other is what one person typed. A shared name is
1963/// agreement; only two sets with nothing at all in common are a difference
1964/// worth showing.
1965///
1966/// Splitting is done here rather than by the caller because a genre tag is
1967/// written in every shape: several tag values, or one value holding
1968/// `Rock, Pop`, `Rock; Pop` or `Rock / Pop`. All of them mean a list.
1969pub fn verdict_set(theirs: &[String], yours: &[String]) -> Verdict {
1970    let split = |values: &[String]| -> Vec<String> {
1971        values
1972            .iter()
1973            .flat_map(|value| value.split([',', ';', '/']))
1974            .map(crate::text::normalize)
1975            .filter(|name| !name.is_empty())
1976            .collect()
1977    };
1978    let (mine, other) = (split(theirs), split(yours));
1979    if other.is_empty() {
1980        return Verdict::NothingToCompare;
1981    }
1982    if mine.iter().any(|name| other.contains(name)) {
1983        return Verdict::Agrees;
1984    }
1985    Verdict::Differs {
1986        theirs: theirs.join(", "),
1987        yours: yours.join(", "),
1988    }
1989}
1990
1991/// Compares two dates written at different precisions.
1992///
1993/// The plain [`verdict`] is wrong for dates and would be wrong on nearly every
1994/// album: MusicBrainz answers `1973-03-01` where a tag almost always holds
1995/// `1973`, and reporting that as a disagreement would fill the report with
1996/// noise on the first run and teach the reader to stop looking.
1997///
1998/// So when either side gives only a year, only the years are compared. When
1999/// both are precise, they are compared as they are — two full dates that
2000/// differ really are a disagreement.
2001pub fn verdict_date(theirs: &str, yours: Option<&str>) -> Verdict {
2002    let Some(yours) = yours.map(str::trim).filter(|y| !y.is_empty()) else {
2003        return Verdict::NothingToCompare;
2004    };
2005    let theirs = theirs.trim();
2006
2007    fn year(text: &str) -> Option<&str> {
2008        let head = text.get(..4)?;
2009        head.chars().all(|c| c.is_ascii_digit()).then_some(head)
2010    }
2011    let (Some(mine), Some(other)) = (year(theirs), year(yours)) else {
2012        return verdict(theirs, Some(yours));
2013    };
2014
2015    // One side is a bare year: that is the precision of the comparison, not a
2016    // difference of opinion about the date.
2017    let bare = theirs.len() == 4 || yours.len() == 4;
2018    let same = match bare {
2019        true => mine == other,
2020        false => crate::text::normalize(theirs) == crate::text::normalize(yours),
2021    };
2022    match same {
2023        true => Verdict::Agrees,
2024        false => Verdict::Differs {
2025            theirs: theirs.to_string(),
2026            yours: yours.to_string(),
2027        },
2028    }
2029}

2049/// Reads the layer; `Ok(None)` when nothing has ever been fetched.

2524/// Reads back what [`to_json`] wrote.
2525///
2526/// Unknown versions are refused rather than read approximately. Version 1 is
2527/// the one explicit migration: its record shape is unchanged and it simply
2528/// predates the `reviews` array.
2529///
2530/// Malformed tables and duplicate entity/source snapshots are refused so a
2531/// subsequent save cannot discard data or preserve an arbitrary first answer.
2532/// An unreadable confidence remains evidence with a zero-score match, never
2533/// an inferred exact attachment.

2541            found,
2542            expected: SOURCES_FORMAT_VERSION,

2544    }
2545
2546    if value.get("records").and_then(Json::as_arr).is_none() {
2547        return Err(StoreError::Invalid("source records must be an array"));
2548    }
2549    for table in ["reviews", "credit_exclusions"] {
2550        if value.get(table).is_some_and(|rows| rows.as_arr().is_none()) {
2551            return Err(StoreError::Invalid("source tables must be arrays"));
2552        }
