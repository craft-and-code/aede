CLI — Commands⌄

Build and inspect

  • scan Read watched music folders into the local catalog
  • roots List, add, remove, or exclude watched folders
  • stats Show the library's size, quality, and completeness
  • doctor Find missing metadata, duplicates, and other catalog issues
  • file Inspect one audio file directly, without the catalog

Preserve and administer

  • serve Serve the local HTTP/JSON/WebSocket catalog API and coordinate CLI writes
  • cancel Request cancellation of a delegated scan or fetch on the local server
  • check Verify the checksums stored in audio containers
  • reset Remove the catalog snapshot, including watched roots, while keeping separate stores
  • backup Save the catalog, sources, and personal data together
  • restore Restore a previously saved Aède backup
  • rules List, export, or import reproducible personal decisions
  • help Show the command index or the page for one command

Enrich and correct

  • analyze Analyze albums with FlacCompagnon and optionally save one JSON report per album
  • credits Measure MusicBrainz recording/work credit coverage and locate gaps
  • credit Add a manual credit or exclude/restore one sourced credit without touching tags
  • spectrum Create spectrograms beside the selected music
  • import Import acoustic analyses from FlacCompagnon
  • sources Inspect, export, import, or remove externally sourced data
  • review Resolve uncertain or conflicting source identities without changing tags
  • fetch Enrich artists, albums, tracks, and artwork from chosen sources
  • missing List credited studio albums that the local shelf does not hold
  • merge Record that two local artist spellings name one person
  • extract Write artwork already embedded in audio files beside the music
  • fingerprint Compute acoustic fingerprints without using the network

Find and select

  • play Play local music
  • query Select tracks with the relational query language

  • collections List the saved dynamic collections
  • search Search graph objects and source-only contributors, plus optional notes, comments, or lyrics
  • export Export the catalog as JSON or a table

  • album Show one album's tracks, credits, and sources

  • work Show one composition and the recordings that realize it
  • release-group Show the album identity shared by every local edition

DSP — Audio

Device-rate conversion

Native rate negotiation, bandlimited conversion, filter state and validation limits.

The sample rate is the number of PCM frames per second, for example 44100 Hz (44.1 kHz). It is not the file's bitrate or the DAC's integer bit depth. Changing it requires reconstructing/filtering the signal, then sampling at new times; merely dropping or duplicating samples would introduce errors.

Automatic native negotiation#

The native player chooses a compatible device format/channel count and rate. It prefers floating-point formats before comparing rate distance, so a supported floating format at a different rate can be chosen ahead of a closer integer format. Read the reported source/output rates; a source marked 96 kHz does not imply that the device receives 96 kHz.

aede play /path/to/96k-song.flac

There is no current CLI output-rate selector. If decoded and selected rates match, Aède bypasses its converter. Otherwise its decoding thread uses stateful bandlimited conversion before gain/tone and final protection. The ffplay fallback receives the decoded rate; any device-rate conversion performed by ffplay/system lies outside Aède's converter diagnostics.

Why filtering matters#

Nyquist is half the sample rate. Frequencies above the new Nyquist cannot be represented and can fold into false lower frequencies (aliasing). Downsampling therefore filters the high end before changing rate. Upsampling creates additional sample positions; it does not restore detail absent from the source or make a lossy recording lossless.

Aède uses Rubato FFT conversion for ordinary fixed rate pairs and sinc conversion for unusual ratios. Converter state is retained across blocks. Startup filter delay is removed; the tail is drained at the end of an uninterrupted stream. Compatible consecutive tracks share state and cumulative frame boundaries, so each file is not separately rounded/reset. Skips or incompatible formats discard the pending processing state.

Validation and limits#

Software signal tests cover documented rate/tone grids, with at most 0.1 dB passband error through 80% of the lower Nyquist, at least 80 dB residual/alias rejection and at most one frame residual phase delay. The high-frequency transition beyond that passband is characterized separately. These values are test coverage, not a promise for every signal, DAC, latency or NAS CPU. The DSP review records the exact checks and limits.

The interactive example illustrates sample positions and the need for a low-pass filter; it is not a Rust-converter benchmark. Device buffering and physical joins still need hardware measurement; see Continuity.
