CLI — Commands⌄

Preserve and administer

  • accounts Manage local accounts
  • serve Serve the local HTTP/JSON/WebSocket catalog API and coordinate CLI writes
  • cancel Request cancellation of a delegated scan or fetch on the local server
  • check Verify the checksums stored in audio containers
  • reset Remove the catalog snapshot, including watched roots, while keeping separate stores
  • backup Save the catalog, sources, and personal data together
  • restore Restore a previously saved Aède backup
  • rules List, export, or import reproducible personal decisions
  • help Show the command index or the page for one command

Build and inspect

  • scan Read watched music folders into the local catalog
  • roots List, add, remove, or exclude watched folders
  • stats Show the library's size, quality, and completeness
  • doctor Find missing metadata, duplicates, and other catalog issues
  • file Inspect one audio file directly, without the catalog

Enrich and correct

  • analyze Analyze albums with FlacCompagnon and optionally save one JSON report per album
  • credits Measure recording, work and edition credit coverage
  • credit Add a manual credit or exclude/restore one sourced credit without touching tags
  • spectrum Create spectrograms beside the selected music
  • import Import acoustic analyses from FlacCompagnon
  • sources Inspect, export, import, or remove externally sourced data
  • review Resolve uncertain or conflicting source identities without changing tags
  • fetch Enrich artists, albums, tracks, and artwork from chosen sources
  • missing List credited studio albums that the local shelf does not hold
  • merge Record that two local artist spellings name one person
  • extract Write artwork already embedded in audio files beside the music
  • fingerprint Compute acoustic fingerprints without using the network

Find and select

  • copy Copy a selection to a player, card, or other destination
  • playlist Write portable playlists in album and artist folders
  • play Play local music
  • query Select tracks with the relational query language
  • collection Save, run, or remove a named dynamic collection
  • collections List the saved dynamic collections
  • search Search graph objects and source-only contributors, plus optional notes, comments, or lyrics
  • export Export the catalog as JSON or a table

Browse the catalog

  • relations List local and sourced graph relationships with stable IDs
  • relation Inspect, annotate, or label one graph relationship
  • artists List artists in the catalog
  • countries Summarize artists by their MusicBrainz origin
  • albums List albums in the catalog
  • genres List genres in the catalog
  • genre Show albums and artists carrying one genre
  • labels List record labels in the catalog
  • label Show a label's catalog and artists; check a Discogs profile when needed
  • years Break the catalog down by release year
  • artist Show a local artist or a source-only credited contributor and their links
  • album Show one album's tracks, credits, and sources
  • track Show a track's album, credits, tags, and technical facts
  • recording Show one recording, its local placements, and sourced work links
  • work Show one composition and the recordings that realize it
  • release-group Show the album identity shared by every local edition

Personalise

  • love Mark an artist, album, or track as a favourite
  • rate Give an artist, album, or track a personal rating
  • note Read or write a personal note
  • tag Attach or remove personal labels
  • played Manually record a listen made outside Aède, or undo its latest record with --remove
  • favourites List everything marked as a favourite
  • notes List, export, or import personal notes
  • history Show listening history, newest first

Server — API

Genres, labels, works and editions

Follow graph relationships and distinguish a composition from its recordings and editions.

These graph-navigation routes use the common page and selector rules. GET returns HTTP 200 on success; HEAD validates the same parameters and returns the same status/headers with no body. Detail relationships are complete arrays, not paginated lists. Data comes from the local catalog, never an automatic web lookup.

GET /api/v1/genres#

Parameters: q or name (normalized name substring), sort=catalog|name, order=asc|desc, offset, limit.

curl --get 'http://127.0.0.1:8787/api/v1/genres' --data-urlencode 'q=jazz'

Each page item contains kind:"genre",reference,name,release_count,track_count. The counts describe graph links, not whether every file has an explicit genre tag. No match is an empty page. Passing both text selectors, duplicate parameters or an unsupported sort gives 400.

HEAD /api/v1/genres#

Same filters, without page JSON; curl -I 'http://127.0.0.1:8787/api/v1/genres?limit=1'.

GET /api/v1/genre#

Exactly one ref or name; no pagination.

curl --get 'http://127.0.0.1:8787/api/v1/genre' --data-urlencode 'name=Jazz'

Returns kind:"genre",reference,name,releases,tracks. Track links include inherited album genres, so a track can appear without its own genre tag. Follow references with /album and /track. Ambiguous names return 409/candidates; absent genres return 404.

HEAD /api/v1/genre#

Same selection/status, with no detail body.

GET /api/v1/labels#

Parameters: q or name, exact case-sensitive mbid, sort=catalog|name, order, offset, limit.

curl --get 'http://127.0.0.1:8787/api/v1/labels' --data-urlencode 'q=Blue Note'

Each item is kind:"label",reference,name,mbid,release_count; mbid can be null. This is the catalog's labels, not a label biography or an automatic Discogs request. No matches gives an empty page; unsupported/duplicate parameters give 400.

HEAD /api/v1/labels#

Same list validation with no body; curl -I 'http://127.0.0.1:8787/api/v1/labels?limit=1'.

GET /api/v1/label#

Exactly one ref or name; no pagination.

curl --get 'http://127.0.0.1:8787/api/v1/label' --data-urlencode 'name=Blue Note'

Returns kind:"label",reference,name,mbid,releases. Follow each album reference for its local edition. Missing labels return 404; ambiguous labels return 409 with candidates. This endpoint does not return every prose panel shown by the CLI.

HEAD /api/v1/label#

Validates the same label selection and omits its JSON body.

GET /api/v1/works#

A work is a composition, distinct from a recorded interpretation. Parameters: q or name (title substring), exact mbid, sort=catalog|name|title, order, offset, limit. name/title sorts are aliases.

curl --get 'http://127.0.0.1:8787/api/v1/works' --data-urlencode 'q=Concerto'

Items contain kind:"work",reference,title,mbid,recording_count. Only works represented in the local graph appear. A fetched work claim alone does not create a local work. No result means an empty page, not proof that the composer never wrote it. Invalid parameters return 400.

HEAD /api/v1/works#

Same parameters/status without JSON; curl -I 'http://127.0.0.1:8787/api/v1/works?limit=1'.

GET /api/v1/work#

Exactly one ref or name; a MusicBrainz work identifier may be passed through name. No pagination.

curl --get 'http://127.0.0.1:8787/api/v1/work' --data-urlencode 'name=Concerto'

Returns kind:"work",reference,title,mbid,recordings. The array links local interpretations of that work; follow /recording and then /track to reach files. 409 means several compositions matched; 404 means none is represented locally. No missing work is fetched by this request.

HEAD /api/v1/work#

Same selection and errors, no detail body.

GET /api/v1/release-groups#

A release group describes an album identity shared by its editions, while a release is a particular local edition. Parameters: q or name, exact mbid, sort=catalog|name|title, order, offset, limit.

curl --get 'http://127.0.0.1:8787/api/v1/release-groups' --data-urlencode 'q=Back in Black'

Items contain kind:"release_group",reference,title,mbid,release_count. release_count counts the local editions linked to this identity, not all editions worldwide. No result is an empty page; conflicting/unsupported parameters give 400.

HEAD /api/v1/release-groups#

Same validation and headers/status only; curl -I 'http://127.0.0.1:8787/api/v1/release-groups?limit=1'.

GET /api/v1/release-group#

Exactly one ref or name; MusicBrainz identifiers can be supplied as name. No pagination.

curl --get 'http://127.0.0.1:8787/api/v1/release-group' --data-urlencode 'name=Back in Black'

Returns kind:"release_group",reference,title,mbid,releases. Follow each reference through /album to compare local editions. Ambiguity returns 409/candidates, absence 404. This is neither the external full discography nor a missing-album calculation.

HEAD /api/v1/release-group#

Same entity resolution and status without JSON.
