CLI — Commands⌄

Preserve and administer

  • accounts Manage local accounts
  • serve Serve the local HTTP/JSON/WebSocket catalog API and coordinate CLI writes
  • cancel Request cancellation of a delegated scan or fetch on the local server
  • check Verify the checksums stored in audio containers
  • reset Remove the catalog snapshot, including watched roots, while keeping separate stores
  • backup Save the catalog, sources, and personal data together
  • restore Restore a previously saved Aède backup
  • rules List, export, or import reproducible personal decisions
  • help Show the command index or the page for one command

Build and inspect

  • scan Read watched music folders into the local catalog
  • roots List, add, remove, or exclude watched folders
  • stats Show the library's size, quality, and completeness
  • doctor Find missing metadata, duplicates, and other catalog issues
  • file Inspect one audio file directly, without the catalog

Enrich and correct

  • analyze Analyze albums with FlacCompagnon and optionally save one JSON report per album
  • credits Measure recording, work and edition credit coverage
  • credit Add a manual credit or exclude/restore one sourced credit without touching tags
  • spectrum Create spectrograms beside the selected music
  • import Import acoustic analyses from FlacCompagnon
  • sources Inspect, export, import, or remove externally sourced data
  • review Resolve uncertain or conflicting source identities without changing tags
  • fetch Enrich artists, albums, tracks, and artwork from chosen sources
  • missing List credited studio albums that the local shelf does not hold
  • merge Record that two local artist spellings name one person
  • extract Write artwork already embedded in audio files beside the music
  • fingerprint Compute acoustic fingerprints without using the network

Find and select

  • copy Copy a selection to a player, card, or other destination
  • playlist Write portable playlists in album and artist folders
  • play Play local music
  • query Select tracks with the relational query language
  • collection Save, run, or remove a named dynamic collection
  • collections List the saved dynamic collections
  • search Search graph objects and source-only contributors, plus optional notes, comments, or lyrics
  • export Export the catalog as JSON or a table

Browse the catalog

  • relations List local and sourced graph relationships with stable IDs
  • relation Inspect, annotate, or label one graph relationship
  • artists List artists in the catalog
  • countries Summarize artists by their MusicBrainz origin
  • albums List albums in the catalog
  • genres List genres in the catalog
  • genre Show albums and artists carrying one genre
  • labels List record labels in the catalog
  • label Show a label's catalog and artists; check a Discogs profile when needed
  • years Break the catalog down by release year
  • artist Show a local artist or a source-only credited contributor and their links
  • album Show one album's tracks, credits, and sources
  • track Show a track's album, credits, tags, and technical facts
  • recording Show one recording, its local placements, and sourced work links
  • work Show one composition and the recordings that realize it
  • release-group Show the album identity shared by every local edition

Personalise

  • love Mark an artist, album, or track as a favourite
  • rate Give an artist, album, or track a personal rating
  • note Read or write a personal note
  • tag Attach or remove personal labels
  • played Manually record a listen made outside Aède, or undo its latest record with --remove
  • favourites List everything marked as a favourite
  • notes List, export, or import personal notes
  • history Show listening history, newest first

What is counted#

Code lines are physical lines, including comments and blank lines, in the supported source files under crates/, tools/ and site/. Nonblank lines are reported separately. The crate table separates production, test/support and example code. Test code lines include integration tests and fixtures written in a source language; that is a different measure from the active unit-test inventory.

Generated output, build caches, vendored files, hidden directories, symlinks, music/images, JSON fixtures, Cargo manifests/lockfiles and Markdown are excluded from code lines. Documentation has its own file/page counts. A published page counts once per language, including an explicitly labelled English fallback when a topic has no French translation. The script reuses the publisher's page catalog rather than a separate list.

Active Rust unit tests come from compiled workspace library and binary test harnesses. The script lists registered tests, subtracts ignored tests and publishes a conservative rounded lower bound such as “more than 1,400 active unit tests”. It does not count #[test] text. Integration tests, example tests, doctests and Python helper tests are outside this TU count, even though they remain part of verification.

The inventory records the toolchain, host and feature configuration: conditional tests can differ between platforms or feature sets. Listing a test does not execute it. The published TU figure is available only when an inventory of the current Rust/Cargo sources has been supplied; a missing or stale inventory cannot silently become a current test count. See the verification workflow and current state for actual validation results.

Reproduce the report#

From the repository root, Python 3.9 or later is sufficient for source measurements; no package installation or network request is needed:

python3 tools/project-stats.py
python3 tools/project-stats.py --json

To include active TUs, first provide the existing Rust/native build prerequisites from the installation guide. Fetch the locked dependencies explicitly if they are not already cached, then build/list test harnesses offline:

cargo fetch --locked
python3 tools/project-stats.py --tests --output target/project-stats.json
python3 tools/build-site.py --check --project-stats target/project-stats.json

--tests does not run the test bodies, play audio or access music files. Use tools/check.sh for the complete checks; it also generates the inventory and publishes the documentation from it. The Site workflow generates its own inventory for the Linux/default-feature build. The machine-readable JSON retains exact measurements and provenance for verification; the public TU display stays rounded. Do not commit generated reports from target/ or dist-site/.

For another configuration, use --no-default-features and/or --features "...". Cargo respects the existing CARGO_TARGET_DIR; an alternative inventory can be reused with --test-inventory PATH only while its Rust/Cargo source fingerprint still matches. Running the publisher without --project-stats still generates fresh source statistics and explicitly leaves the TU figure unavailable.
