## Aède 0.7.5

### Cached label logos for native clients

The catalogue API now advertises `label_logos`, reports logo availability in label lists/details and serves the existing cached JPEG or static PNG through the artwork route. Phémios can show the same mark beside a label name and in its detail header. Browsing never contacts Fanart.tv or modifies source audio, tags or artwork.

Logos require an exact local MusicBrainz identifier or a trusted identified/accepted identity. Ambiguous and rejected provider suggestions do not become an artwork authority. Existing filesystem, media-size and account/parental admission rules remain applicable. Fetching logos remains an explicit Fanart.tv enrichment with its configured key; an unavailable image remains a normal client fallback.

### Biographies follow the requested language

Clients can explicitly request summaries in their interface language. A retained English biography no longer blocks a French lookup merely because the same Wikidata entity was already cached. A completed preferred-language lookup records its ordered preference, including a genuine absence or an English fallback, so ordinary repeated enrichment does not query the same result endlessly. An explicit full refresh still permits a retry.

Existing biographies remain intact on network errors, malformed replies or a response in another language than the requested article. Attribution, the actual text language and explicit review rejections are retained. Labels prefer trusted Wikipedia prose and keep Discogs as an original-language fallback. This does not translate biographies or automatically fetch providers when browsing or changing a client preference.

### Compatibility and download choices

The optional source-cache language context is additive: existing source stores remain readable. The catalogue format and format-3 personal-store rules introduced in 0.7.4 are unchanged. Aède 0.7.4 can read current personal data; 0.7.3 and earlier still require a compatible pre-upgrade backup. Older clients can ignore the new fields, and older servers remain usable with unavailable logo controls. Clients selecting the latest published stable engine will select 0.7.5 only after its draft release is published.

Choose **CLI** for terminal/headless use or **App** for the graphical local server. CLI archives cover **macOS Apple Silicon**, **Linux x86_64 musl**, **Linux ARM64 musl** and **Windows x64**. App installers cover **macOS Apple Silicon**, **Linux x86_64** and **Windows x64**. No macOS Intel, Linux ARM64 App or 32-bit ARM package is provided. Every package has its SHA-256 sidecar. Linux CLI playback requires a separately installed ffplay; native ALSA/strict bit-perfect remains a GNU source-build capability.

### Verification boundaries

Regressions cover trusted/uncertain label identities, missing and redirected artwork, HTTP presence/image agreement, legacy biography refreshes, failed refresh preservation, language fallback/absence caching, malformed cache context and rejected claims. Local host gates and tagged GitHub builds remain separate evidence from installed Linux/Windows, live-provider and physical audio/device acceptance.

No third-party dependency or advisory exception changes. Existing dependency findings remain documented in the [engine assessment](https://github.com/craft-and-code/aede/blob/v0.7.5/docs/coding/dependency-audit.md) and [App assessment](https://github.com/craft-and-code/aede/blob/v0.7.5/docs/coding/desktop-dependencies.md).
