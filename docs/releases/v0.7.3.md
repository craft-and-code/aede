## Aède 0.7.3

### Linux ARM64 CLI for headless hosts

The release workflow now prepares `aede-CLI-0.7.3-Linux-ARM64.tar.gz` and its SHA-256 sidecar for 64-bit ARM Linux hosts. Select this archive when `uname -m` on the destination machine reports `aarch64` or `arm64`. The existing `Linux-x86_64` archive remains for Intel/AMD 64-bit Linux; it cannot run on an ARM64 NAS. ARM32 systems such as `armv7l` need a different build and are not packaged here.

The new target is `aarch64-unknown-linux-musl`, built with Rust 1.89 and the locked dependencies on a native ARM64 GitHub runner. Tests run on that architecture before packaging. Both Linux CLI jobs require the FFmpeg conversion regressions and verify the executable's ELF architecture, absence of a dynamic loader/shared-library requirement, version output and help startup before archiving it. No emulation or runner-specific CPU optimization is used.

The musl CLI archives are statically linked to avoid a matching glibc requirement. Scanning, cataloguing and serving the library do not need FFmpeg; local playback through these archives requires a separately installed ffplay. Native ALSA and strict bit-perfect output remain GNU source-build capabilities, not features of these musl archives. Kernel compatibility, NAS permissions, storage capacity and physical output still require validation on the destination host. See the [installation guide](https://github.com/craft-and-code/aede/blob/v0.7.3/docs/manual/install.md).

### Existing platforms and playback correction

CLI archives remain available for macOS Apple Silicon, Linux x86_64 and Windows x64. App installers remain available for macOS Apple Silicon, Linux x86_64 and Windows x64; this patch does not add a Linux ARM64 graphical App. Every package has a separate SHA-256 sidecar. Builds remain unsigned, and the workflow creates a **draft** only after every CLI and App platform job succeeds.

The bounded, shutdown-interruptible PCM failure-close correction from [0.7.2](https://github.com/craft-and-code/aede/blob/v0.7.3/docs/releases/v0.7.2.md) is retained, including its original MD5 and late-acknowledgement regressions. Earlier tags and their packages are not replaced. Client stable-source preparation does not select a draft; publication remains a separate maintainer decision.

### Dependency findings remain visible

No third-party dependency is updated. Tokio remains at 1.53.3, clipboard-win at 5.4.3 and FlacCompagnon core at published 0.9.6. The engine's paste maintenance advisory (RUSTSEC-2024-0436), the App's GLib unsoundness advisory (RUSTSEC-2024-0429) and proc-macro-error maintenance advisory (RUSTSEC-2024-0370) remain visible, with empty advisory ignore lists. Both strict cargo-deny checks still fail, including the documented engine workspace-dependency diagnostics. Functional build success does not clear these findings or audit the pinned FlacCompagnon Git source. See the [dependency assessment](https://github.com/craft-and-code/aede/blob/v0.7.3/docs/coding/dependency-audit.md) and [desktop findings](https://github.com/craft-and-code/aede/blob/v0.7.3/docs/coding/desktop-dependencies.md).
