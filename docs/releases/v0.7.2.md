## Aède 0.7.2

### Reliable playback failure closure

After a playback error, Aède now sends its JSON error and WebSocket Close, then drives the peer close handshake instead of immediately dropping the connection with client acknowledgements still in flight. Cleanup has a one-second deadline, a 64-message cap and a 16-KiB received-payload threshold under the existing 4-KiB message limit. Server shutdown interrupts the wait immediately.

Cleanup acknowledgements never extend listening history or restart audio. A real FLAC queue regression verifies that a decoded-content MD5 failure preserves the completed preceding listen, keeps the failed occurrence incomplete and never starts the following track. The original source files and tags remain untouched. Fixed diagnostics distinguish notification send failures, send/close deadlines, transport errors and cleanup limits without logging credentials, private paths or client payloads.

### Regression coverage and platform checks

Seven new regressions cover the peer close exchange, late acknowledgements, bounded cleanup, disconnection and retained shutdown. Both original MD5 tests remain unchanged. The existing shutdown timing assertions remain enabled and unchanged.

Before this version was prepared, the corrected source passed all six jobs in [native CI run 40069139533](https://github.com/craft-and-code/aede/actions/runs/40069139533), including the previously failing MD5 scenario and all new cases on Linux GNU, Windows and macOS. Linux passed 2,943 Rust cases with one pre-existing ignored physical ALSA lifecycle test; Windows passed 2,744 with none ignored. Root jobs use Rust 1.89. The local full gate passed 2,941 Rust cases, and 90 bounded MD5/close repetitions also passed. These results validate the corrected behavior without establishing the precise cause of the historical intermittent Linux EOF or certifying physical audio output.

### Existing features and dependency findings

This release includes the shared audio foundation, server App maintenance and Windows folder-admission fixes described in the [0.7.1 notes](https://github.com/craft-and-code/aede/blob/v0.7.2/docs/releases/v0.7.1.md). The `v0.7.1` tag and its downloads remain unchanged; 0.7.2 packages the playback correction under a new tag. Client stable-source selection can use 0.7.2 only after it is published as a stable release; a draft is not selected automatically.

No third-party dependency is updated for this patch. Tokio remains at 1.53.3, clipboard-win at 5.4.3 and FlacCompagnon core at published 0.9.6. The engine's paste maintenance advisory (RUSTSEC-2024-0436), the App's GLib unsoundness advisory (RUSTSEC-2024-0429) and proc-macro-error maintenance advisory (RUSTSEC-2024-0370) remain visible, with empty advisory ignore lists. Both strict cargo-deny checks still fail, including the documented engine workspace-dependency diagnostics. Passing functional CI does not clear these findings. See the [dependency assessment](https://github.com/craft-and-code/aede/blob/v0.7.2/docs/coding/dependency-audit.md) and [desktop findings](https://github.com/craft-and-code/aede/blob/v0.7.2/docs/coding/desktop-dependencies.md).

### Downloads and release preparation

Choose an `aede-CLI-0.7.2-…` archive for terminal use or an `aede-App-0.7.2-…` installer for the local HTTPS server console. Packages target macOS Apple Silicon, Linux x86_64 and Windows x64, with separate SHA-256 sidecars. There is no Mac Intel build. Linux CLI archives use ffplay for playback and require FFmpeg to be installed separately. The App keeps its own private data directory, separate from ordinary CLI data.

Builds are unsigned. The release workflow creates a **draft** after all platform jobs succeed; stable publication requires a separate maintainer decision. Physical gapless/bit-perfect output, real renderer interoperability and interactive Windows console/clipboard acceptance remain separate from software CI.
