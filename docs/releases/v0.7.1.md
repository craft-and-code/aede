## Aède 0.7.1

### Safer folder admission and Windows fixes

Scan-root validation now checks raw parent components before canonicalizing the final path. A path such as `file/../music` is refused when its parent is a file, even if the final music directory exists. Valid directory parents remain supported; refusal preserves the retained catalogue and private data. No audio file or tag is modified.

Windows path fixtures now retain the traversal they are intended to test. Media timestamp tests use a writable disposable file without changing its contents, and forgetting previews compare canonical data paths. Desktop archive creation also passes Windows warnings-denied Clippy while retaining exclusive creation and private Unix permissions. All previous behavioral assertions remain enabled, with nine additional regression tests.

The corrected source passed engine and App CI on macOS, Linux and Windows before this version was prepared. Both Windows-only regressions and all formerly failing Windows cases passed. The existing Linux physical ALSA lifecycle test remains explicitly ignored without a selected hardware device; software CI does not certify physical output or interactive Windows console/clipboard behavior.

### Shared audio and server App

This version carries forward the shared `aede-audio` and `aede-dsp` foundation, catalogue/account ownership checks, playback lifetime fixes and desktop maintenance described in the [0.7.0 notes](https://github.com/craft-and-code/aede/blob/v0.7.1/docs/releases/v0.7.0.md). The App can open its data folder, renew its generated administrator password while stopped, or select an empty server profile while retaining the previous store and archived configuration.

Phémios and FlacCompagnon can select the shared crates only after this version is published as a stable release. Creating a tag or a draft does not make it eligible for their automatic stable-source selection. The earlier 0.7.0 release workflow did not produce a release.

### Dependency findings remain visible

This patch changes Aède's own version metadata without updating third-party dependencies. Tokio remains at 1.53.3, clipboard-win at 5.4.3 and FlacCompagnon core at published 0.9.6.

The engine's `paste` maintenance advisory (RUSTSEC-2024-0436), the App's GLib unsoundness advisory (RUSTSEC-2024-0429) and `proc-macro-error` maintenance advisory (RUSTSEC-2024-0370) remain open. Both cargo-deny checks still fail, including the documented engine workspace-dependency diagnostics. Advisory ignore lists stay empty. See the [dependency assessment](https://github.com/craft-and-code/aede/blob/v0.7.1/docs/coding/dependency-audit.md) and [desktop findings](https://github.com/craft-and-code/aede/blob/v0.7.1/docs/coding/desktop-dependencies.md); passing functional builds does not resolve these findings.

### Downloads and release status

Choose an `aede-CLI-0.7.1-…` archive for terminal use or an `aede-App-0.7.1-…` installer for the local HTTPS server console. App data remains separate from ordinary CLI data. Packages target macOS Apple Silicon, Linux x86_64 and Windows x64; there is no Mac Intel build. Linux CLI archives use ffplay for playback and require FFmpeg to be installed separately.

The release workflow tests and builds each platform, attaches packages and SHA-256 sidecars, and creates an unsigned **draft** only after every platform succeeds. Publication requires a separate maintainer decision. Real hardware interoperability, digital bit-perfect output and installer acceptance remain separate from automated software checks.
