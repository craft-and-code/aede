## Aède 0.7.4

### Stable collection identities for navigation shortcuts

Saved collections now have persistent opaque IDs. Renaming a collection or replacing its query retains the same identity; deleting it and creating a new collection with the former name produces a new ID. Clients such as Phémios can keep their navigation shortcuts attached to the intended collection without following a reused name.

The personal API exposes the `collection_identity` capability and accepts an owner-scoped ID for collection reads, rename, deletion and album evaluation. ID and name selectors cannot be combined. Existing name-based CLI/API operations remain available, and IDs never grant access to another account's collections. Name collisions are refused without changing the saved rule or creation date.

### Personal-data migration and older engines

The reader accepts personal-store formats 1 and 2 and deterministically assigns IDs to legacy collections in memory. Reading alone does not rewrite a store. The next successful personal-data write persists these identities in format 3. Malformed, missing format-3 or duplicate collection IDs are refused rather than silently replaced; backup merging retains established local identities and refuses conflicting collection names.

Keep a backup of personal data before upgrading. Aède 0.7.3 and earlier cannot read format 3 and refuse it to prevent losing collection identities. Returning to an older engine requires a compatible pre-upgrade backup, not a rescan or a personal-data reset. The catalogue format and source audio/tag files are unchanged. See [stable collection identity and downgrade limits](https://github.com/craft-and-code/aede/blob/v0.7.4/docs/server/presentation.md#stable-collection-identity).

### Separate CLI and App downloads

CLI archives remain available for **macOS Apple Silicon**, **Linux x86_64**, **Linux ARM64** and **Windows x64**. App installers remain available for **macOS Apple Silicon**, **Linux x86_64** and **Windows x64**; there is no Linux ARM64 graphical App or macOS Intel download. Choose CLI for terminal/headless use and App for the graphical local server. Each package has its own SHA-256 sidecar.

The Linux CLI archives use musl and require a separately installed ffplay for local playback. Native ALSA/strict bit-perfect output remains a GNU source-build capability. The release workflow tests and packages each native target and creates a draft only after every CLI/App job succeeds. Earlier tags and downloads are not replaced. A draft is not selected by clients that resolve the latest published stable Aède release; publish the verified 0.7.4 release before expecting those builds to select its collection support automatically.

### Validation boundaries and retained dependency findings

Migration, identity preservation, delete/recreate, invalid/duplicate IDs, backup conflicts and owner-scoped API selection have regression coverage. Local host gates and the tagged GitHub build are distinct evidence; neither establishes physical audio/device or installed Linux/Windows acceptance.

No third-party dependency is updated. The existing paste maintenance advisory (RUSTSEC-2024-0436), App GLib unsoundness advisory (RUSTSEC-2024-0429), proc-macro-error maintenance advisory (RUSTSEC-2024-0370) and strict cargo-deny workspace diagnostics remain documented, with no new ignore or exception. Functional build success does not clear those findings or audit the pinned FlacCompagnon Git source. See the [dependency assessment](https://github.com/craft-and-code/aede/blob/v0.7.4/docs/coding/dependency-audit.md) and [desktop findings](https://github.com/craft-and-code/aede/blob/v0.7.4/docs/coding/desktop-dependencies.md).
