# Original DSD output over DoP

The unpublished shared `aede-audio` candidate adds DoP 1.1 transport and explicitly requested CoreAudio HAL, WASAPI exclusive/raw and direct ALSA hardware backends. Aède's CLI uses it with `--dsd-output=dop` and an exact native device ID (`coreaudio:<device-UID>`, `wasapi:<endpoint-ID>` or `alsa:hw:<card>,<device>`). Ordinary DSD playback still uses the [listening PCM decoder](native-dsd.md). DoP packs original DSD bits into an integer carrier; it does not run that decoder, a PCM filter, a resampler or gain processing.

The source integration includes the local CLI, FlacCompagnon's explicit DoP preview and Phémios's explicit native DoP mode. PCM remains the default. Aède's server App owns no listening device: it supplies authenticated original DSD words to Phémios, whose native host owns the DAC. Browsers retain PCM. Source verification does not rebuild installed Apps, embedded engines or product bundles.

## Source and transport

The initial profile is uncompressed DSF/DFF at DSD64/128, mono/stereo. Container inspection is shared with the PCM decoder. `dsd::RawSource` retains the read-only regular file, respects declared byte/channel order, reads at most 4,096 bytes per channel and excludes DSF block padding. Seeks address source bits on byte boundaries. The existing measurement/listening PCM filters reuse this source reader without changing their signal processing.

`dop::Reader` produces at most 2,048 sixteen-bit payload words per channel. The oldest source bit occupies payload bit 15, following figure 1 of the [DoP 1.1 specification](https://dsd-guide.com/dop-open-standard). The upper byte alternates `0x05`/`0xFA` on every carrier frame and has the same value on both channels. Source clocks remain 2,822,400/5,644,800 Hz; corresponding carrier rates are 176,400/352,800 frames/s. Carrier framing is not converted PCM precision.

The original valid one-bit length is retained independently of the final carrier word. At most fifteen missing tail bits receive declared balanced DSD silence. The initial hardware profile is stereo: a mono payload is copied bit for bit to both channels, and source metadata remains mono. DSD silence uses `0x6969` in MSB-first payload order. Thirty-two silence frames precede programme bits; pauses and mute preserve marker phase. Pause consumes no programme bits. Mute consumes time while replacing the programme with DSD silence, without multiplying the encoded carrier.

The typed payload queue holds half a second of stereo carrier frames. Native output uses integer storage only: packed little-endian 24-bit, low-aligned sign-extended 24-in-32, or high-aligned 24-in-32. The HAL render callback has no ordinary allocation, filesystem I/O, logging, mutex or PCM processing. Polled backends preallocate write buffers and perform native route queries on their control thread. Source reads and device control use separate workers. Underruns, unexpected callback geometry, reentry, source faults and route changes permanently stop the visit; there is no PCM/ffplay fallback or concealment of a successful visit.

Startup remains on framed DSD silence until the source queue is full or a shorter source reaches validated EOF. A first read burst alone does not admit programme bits: it may contain fewer frames than one hardware buffer. The existing startup deadline still applies.

## Native client handoff

FlacCompagnon opens the existing file player with initial pause/mute held before programme admission. Explicit DoP requires an exact native DAC selection, retains pause/seek/stop/error/cleanup semantics, and offers no software volume. Non-DSD or unsupported sources are refused rather than silently converted.

Phémios requests `dsd_output:"dop"` on the existing authenticated playback WebSocket after confirming `dsd_original_playback`. Normalization, tone, rate conversion and persistent PCM profiles are incompatible with this mode. The server emits `dsd16le` interleaved chronological sixteen-bit words, genuine `source_rate`, `source_samples` and `position_samples`; `sample_rate` is the carrier clock used by ACKs. History clamps the padded final word to original bits. One socket queue retains one DSD clock; Phémios admits tracks separately so DSD64/128 transitions reopen the matching route.

The shared `dop::stream_output::StreamOutput` accepts bounded original words, not float PCM or a downloaded whole track. It buffers at most half a second, duplicates mono bit for bit and opens the backend only after full prefill or validated short EOF. Preparation emits framed silence until final caller admission. The same drivers/renderers handle file and network output; no gain, EQ, crossfade or PCM fallback is applied. Restoration failures remain errors on repeated retirement. A native network client can hold initial pause until `is_admitted()` confirms preparation and final admission, then reapply its latest mute/retirement controls before releasing programme words. A queued Stop/Pause/skip/output change during preparation must not be followed by a programme burst.

Pause/output replacement retires the transport while retaining its exact delivered original-bit position. A DoP seek provides `position_samples` instead of `position_ms`, aligned to sixteen bits except at exact EOF. Final Stop/Seek ACKs include native handoff after close; resumed prefixes are never rounded to milliseconds. Old servers and browser/CD/radio routes retain explicit capability/policy boundaries.

The client withholds the last original-DSD frame ACK until native drain and device restoration succeed. A Stop or failed retirement may still report the truthful full consumed count; the server retains that listening duration while leaving a stopped or abandoned DoP visit incomplete. PCM completion rules are unchanged.

## CoreAudio admission

The user must select a DAC known to support DoP; listing a UID or exposing a high sample rate does not establish that capability. The backend uses Apple's public CoreAudio/CoreFoundation system APIs through an approved isolated FFI module, without a new package dependency. It bypasses CPAL/AudioUnit conversion and the shared mixer.

The first hardware profile requires a physical USB DAC with one active output-only stream, stereo channels 1/2 associated with front left/right, exact nominal rate and matching physical/virtual signed integer storage with 24 valid bits. Virtual I/O must be non-mixable. Float, planar, big-endian, 32-valid-bit, mismatched storage, aggregate, wireless and unspecified channel routes are refused. Broader drivers/formats need independent qualification before admission. Existing supported hardware volume controls must be unity and mute disabled; Aède never changes them. Listening level belongs on the DAC/amplifier.

The backend snapshots the nominal rate and both stream formats, takes an otherwise unowned hog-mode lease, sets the selected formats and verifies readback with a bounded deadline. It refuses an already held lease, including another stream in this process. Preparation callbacks emit only silence until both the source and caller admission are ready. Setup failure rolls back partial changes and returns any rollback failure, including geometry queries and callback-context allocation after taking the lease; close stops and destroys the IOProc, removes property listeners and restores the saved formats before releasing its own lease. Lost ownership or externally changed prepared formats are reported and preserved rather than overwritten.

HAL receives a bounded generation token, never a pointer to a freed Rust object. Callback retirement detaches new visitors and waits for counted visitors before freeing their storage. A stale token cannot address a replacement visit. If a callback cannot quiesce or HAL registration cannot be destroyed, bounded state is retained and that DAC is refused until process exit. Cleanup failures remain errors and cannot seal completed history. Unexpected render unwinding is contained at the C ABI boundary when the build supports unwinding; `panic=abort` retains its process-abort semantics.

## WASAPI and ALSA admission

The approved Windows backend reuses Windows 0.62.2 SDK bindings. One fresh STA control thread owns COM, the exact active endpoint, IAudioClient2 RAW exclusive timer-driven output, endpoint-volume observations and MMCSS registration. Admission requires exact stereo PCM-format storage with 24 valid bits, either packed 24-bit or high-aligned 24-in-32, and the original carrier rate. RAW is requested without an automatic conversion or shared-mode fallback; endpoint mute and master/channel gains must already be neutral. Device invalidation, gain changes, padding errors and a dry buffer stop the visit. Interfaces and MMCSS are released before COM uninitialization and completion. Driver acceptance of RAW is required; the flag alone does not prove physical bit identity.

The Linux backend reuses the existing ALSA 0.11.0 fork and its hardware-observation methods through an explicit path dependency, so consumers do not depend on this workspace's Cargo patch. It opens only the selected nonblocking `hw:` playback substream, verifies hardware identity and one substream, exact rational rate, stereo mapping, disabled resampling and 24 significant bits. Initial representations are S24_3LE and low-aligned S24_LE. Existing hardware controls are observed and retained without changes. Manual start follows a full prefill; xruns/disconnects are errors, with no recovery or PCM-silence insertion. The owned PCM handle is stopped and closed before completion.

Both polled backends bound their hardware/staging capacity to 16,384 frames. Partial writes advance marker phase and published source progress only by accepted frames. Pending original words survive pause/mute changes; pause writes framed DSD silence without discarding those words. Retirement is rechecked after native space queries and immediately before a new transfer; pending words cannot be submitted after a completed query reports cancellation or failure. A transfer already in progress retains only its actually accepted prefix. Owner retirement remains a normal stop, while native I/O and source/route failures remain errors. Neither backend renders encoded DoP through CPAL or the ordinary PCM/DSP path. All platforms hold preparation on silence until the final caller admission check, including replacement after seeking.

Linux GNU CLI builds enable `dop-alsa`. The ordinary static musl build retains no libasound requirement and refuses DoP; custom musl builds may opt into `--features dop-alsa` with a target libasound development/runtime environment. Windows/Linux execution and real DAC recognition still require native acceptance; cross-platform Rust type checking is separate from those checks.

## Controls, progress and file identity

The CLI retains its selection, repeat, shuffle, Next/Previous and Stop rules. Seeking stops/restores the old device visit and prepares a fresh link on the same retained file. It preserves pause/mute, rounds down to a sixteen-bit source boundary and clamps CLI time requests at source EOF. Invalid or already cancelled requests leave a healthy current visit intact. A failure after replacement starts retires the visit permanently. Replacement refusal returns any device restoration failure alongside its admission error and retains both in the retired snapshot. Explicitly closed players cannot be restarted by seeking. Neither track changes nor seeks promise gapless output.

Before starting the first track or a track change, the CLI applies already queued terminal controls. Stop and manual skips do not open or record the unplayed selection. A paused selection waits without opening the DAC, and manual skips retain that pause. Pending seek, repeat and shuffle choices apply before admission; a closed keyboard releases the initial pause, matching ordinary CLI playback.

Queue advancement must explicitly return a successor before another native visit starts. A stopped queue retains its last cursor for presentation; that cursor does not authorize reopening the track. Natural exhaustion, repeat-one/all and real following occurrences retain their ordinary behavior.

Replacement activation must succeed before adopting its source position. If final caller admission or the prepared route fails, the retired old visit retains its final consumed position and the error. The skipped destination cannot enter listening history as delivered audio.

File length/modification stamps are checked during raw visits and before replacement, alongside the original source facts. Replacing the pathname does not adopt another file. These checks do not create an immutable filesystem snapshot or detect writes that preserve all observed metadata; OS filesystem I/O already in progress cannot be forcibly interrupted.

History sums original bits handed to the native output, including final in-flight counts when stopping/seeking, while excluding skipped prefixes and paused time. Any seek leaves the listen incomplete. Natural software completion requires exact source length, successful source EOF, the bounded drain derived from the native buffer/latency properties, and successful device cleanup. Paused output is still polled for faults; an active output with no progress for five seconds fails. HAL progress advances only for successfully encoded source frames. A word removed from the ring and then cleared because of cancellation or failure is not delivered progress and cannot seal source EOF. These counters and drain estimates are not a DAC acknowledgement or a physical bit-identity measurement.

## Verification and remaining acceptance

Headless tests cover known DoP frame vectors, all admitted integer representations, both DSD clocks, DSF bit orders/DFF interleaving, mono duplication, block/channel boundaries and every partial final word. Reader/PCM comparisons retain exact prior measurement/listening output. Mock device tests exercise partial setup rollback, ownership loss, external format changes, cancellation, callbacks after retirement, bounded callback storage, route failure, failed restoration and late faults at EOF. CLI tests cover consumed-bit history, initial/runtime seeks, paused faults and explicit refusals without opening hardware.

Native macOS source compilation/linking and tests remain separate from hardware acceptance. No DAC was started by this verification. Required hardware trials are DoP recognition on a named DAC/driver/macOS version, DSD64/128, the admitted storage formats exposed by that driver, pause/mute/resume, track changes, seeking, unplug/route changes, repeated cleanup and restoration, plus capture where available to establish physical payload identity. Native Windows/Linux execution, target libasound linking and hardware trials remain pending. Direct native DSD beyond DoP, DST, SACD ISO, higher clocks and multichannel output remain outside this implementation.

The cross-platform source follow-up additionally covers nonblocking/partial writes, zero acceptance, marker phase after retries, pause/mute transitions with pending original words, invalid push geometry, and admission held through replacement. Scoped source verification passes 3,163 default-workspace Rust cases and 216 shared-audio all-feature cases. Rust checks of audio, CLI and the three-consumer harness pass Windows x64 GNU/ARM64 gnullvm plus Linux GNU/musl x64/ARM64; musl also checks the explicit ALSA CLI feature. These use Rust 1.99/build-std and compile target C/C++ sources with Zig 0.17.0, plus private Opus 1.6.1 target archives. The Linux ALSA pkg-config input is metadata-only: no target libasound linking or native target execution is claimed. No remote CI or DAC playback was started.
