# Additional shared native decoders

The unpublished `aede-audio` candidate provides progressive WavPack, Musepack, Ogg/Speex and APE PCM under `decode`. Aède and FlacCompagnon use this reader for Rust spectrograms. The common minimal player also sees these inputs; application catalogue/output selectors retain their own supported-format policy. This is decoding, not another DSP. It does not add an analysis engine, normalization, equalization, crossfade, strict output or source/tag writes.

## Profiles and timing

| Codec | Initial native admission | Deliberate limits |
| --- | --- | --- |
| WavPack 5.9.0 | Known-length mono/stereo PCM, integer or IEEE float, including hybrid base streams | No DSD, multichannel blocks, automatic `.wvc` lookup or correction-file promise; hybrid precision remains unknown rather than claiming lossless PCM |
| Musepack libmpcdec r475 | SV7/SV8 header profiles, mono/stereo, known decoded length | Files below 2 GiB (reference reader's signed 32-bit positions), at most 24 hours at 48 kHz; independent generated PCM qualification currently covers SV8, not SV7 |
| libspeex 1.2.1 | Single Ogg stream, narrow/wide/ultra-wide band at 8/16/32 kHz, mono/stereo, 1–16 frames per packet | No chaining/multiplexing; version/header/frame/CRC/sequence/EOS checks; preserve coded PCM because granules alone do not establish an original gapless window |
| Monkey's Audio SDK 13.43 + ape-decoder 0.3.2 | Bounded 3.80–4.10, ordinary little-endian integer mono/stereo; SDK below 3.99, existing Rust backend from 3.99 | No pre-3.80, float, big-endian or signed-8-bit profile; independent historical stereo PCM16 evidence is detailed below; other precisions/profiles remain separately qualified |

The tests compare integer/float/hybrid WavPack, APE and SV8 Musepack against independent PCM references. Musepack's official decoder supplies its playable count and handles synthesis pre-roll; the FFmpeg reference is aligned by its retained 481-frame prefix **only in fixture generation**, never by a new production trim. Speex uses libspeex's standard enabled perceptual enhancement, part of codec reconstruction; it applies no application DSP. Speex reference PCM comes from the official `speexdec` executable, used only to generate fixtures. The FFmpeg implementation differs materially in wideband reconstruction and is not used as a PCM-equivalence oracle for Speex. The tests allow only three PCM16 LSBs against the official Speex reference, including its output quantization.

FlacCompagnon's spectral adapter consumes normalized `f32`, counts complete decoded frames in its existing two passes and feeds the existing FFT/PNG engine. It does not repurpose floating conversion for original-integer precision/authenticity analysis or manufacture MD5 verdicts. These formats' full original-integer analysis applicability is unchanged. Aède retains lazy explicit FFmpeg compatibility for inputs outside native opening admission. A data/CRC error **after** admission cannot restart through another decoder or publish a recovered prefix as complete. Spectral generation `native-extra-v3` invalidates images made before the effective-clock checks, including the previous `native-extra-v1` and `native-extra-v2` generations.

Phémios CUE/APE consumes the same retained-file original PCM16 decoder, without FFmpeg/FFprobe. Its stricter CD-quality policy and bounded sector requests are retained.

## Foreign boundary and budgets

The maintainer approved `ape-decoder` and isolated unsafe FFI to statically compiled reference C libraries. `native/bridge.h`, three small C shims, the approved C++ SDK shim and `src/native/{ffi,io,ape_sdk}.rs` own that boundary. Rust only gives C callbacks onto an already opened regular, read-only file; no codec gets a filesystem name, account, URL or subprocess. Contexts and input boxes have stable addresses, are uniquely owned and movable (`Send`), never `Sync` or shared across decoding workers. C destruction precedes release of callback storage. Rust callbacks catch unwinding and retain I/O errors; they never unwind across C. This does not sandbox a C library or recover undefined behavior/abort/OOM. Upstream changes and advisories still require review.

Musepack's legacy shared table initialization is serialized over the complete public API boundary, including open/decode/drop. WavPack and Speex use independent contexts. No codec work runs in the device callback.

Preflight walks checked extents without retaining a track. WavPack/Musepack have a 65,536-header/packet budget, compressed units at most 16 MiB, and admitted channel/clock/count bounds before foreign allocation. WavPack blocks admit at most 524,288 frames. APE limits its descriptor/header to 4 KiB each, seek table to 4 MiB, stored wrapper to 1 MiB, compressed frame to 16 MiB and decoded frame to 1,048,576 scalar samples. Ogg checks at most 65,536 pages, 65,025 payload bytes per page, a 1-MiB assembled metadata packet and 65,536-byte Speex speech packets. Speex decoded packets hold at most 16 × 640 × 2 samples. The Musepack output buffer is the reference API's 4,608 floats; WavPack output visits request 4,096 frames. Final validation rejects incomplete interleaves, non-finite samples, count overflow, declared-length overrun and incomplete known-length EOF. These are adapter budgets, not a universal bound on all upstream allocations or process RSS.

Visits check caller ownership before/after bounded codec work and before publication, including skipped Musepack pre-roll and Ogg pages. Cancellation/data failure retires a visit permanently. An already running file read, initial header admission or foreign codec call cannot be forcibly interrupted. Account/source owners remain responsible for calling admission and discarding retired results. No account state is stored in the shared crate.

## Reproduction and release boundary

Fixtures, generator commands and provenance are in `crates/aede-audio/tests/fixtures/native-extra/README.md`. The source archives and per-file hashes are documented in `crates/aede-audio/vendor/README.md`. `THIRD_PARTY_NOTICES.txt` contains BSD/Zlib and APE licence texts; clients can access the same text through `native::THIRD_PARTY_NOTICES` and must include it in binary redistribution materials. The C shims link statically using the already available `cc` build dependency. C11 and C++11 compilers are required (including a matching static C++ runtime on musl); no new runtime executable, automatic download, assembly or native codec thread is added. `decode` is optional, so the browser's DSP-only feature does not compile/link the C readers.

macOS fixture tests are software evidence, not Windows/Linux/musl/ARM64 or physical listening acceptance. These platforms must run the same fixtures and static-link release checks before a coordinated publication. Stable-source pins remain unchanged until that release: a temporary compatible Aède/FlacCompagnon source composition verifies candidate APIs without claiming that published releases already contain them. No application rebuild is required for these library checks.

The [vendor security notes](../../crates/aede-audio/vendor/README.md#security-backport) retain Speex's upstream non-owned-buffer fix and the independent failing/passing C sentinel regression. They also record libmpcdec r475's unmaintained status and its additional sanitizer/fuzz qualification required before publication. Passing musical/reference fixtures is not a claim of complete C memory safety.

### Musepack seek admission before FFI

SV7 must declare a positive frame count before C context construction. A zero-frame header with otherwise admissible legacy fields previously passed Rust admission, underflowed the C parser's unsigned sample count after synthesis-delay subtraction, and triggered an invalid signed seek-stride shift under UBSan before output properties could be validated. Shared-reader, FlacCompagnon PCM/spectral and Aède image-publication regressions reject that header while preserving source bytes; the positive one-frame preflight boundary remains admitted. This synthetic boundary check does not extend independent SV7 PCM qualification.

SV8 is checked as one authoritative SH header. Every SO reference must resolve to a validated packet boundary (including a zero self-reference); it cannot make the C reader treat bytes inside AP as a new header. Each ST exponent plus the SH audio-block power must leave the reference expression `1152 << power` positive and representable in signed 32-bit C (`power <= 20`). This is checked before constructing any C context. A malformed generated input with power 29 previously passed the Rust gate and triggered a shift error under UBSan in `mpc_demux_ST`; this is evidence of undefined C arithmetic, not a claim of a demonstrated exploit or an ordinary-build crash. A second SH cannot change the channel/block contract after preflight. The largest safe seek power and zero references retain identical decoded PCM in the original SV8 fixture.

The separate local Musepack word-assembly patch makes bit-reader shifts and the 31-bit mask unsigned before arithmetic. Its standalone UBSan regression previously failed on a high-bit byte and now passes across all bit offsets; independent SV8 PCM remains the reference for the audio. These focused corrections do not qualify every legacy libmpcdec operation. Complete sanitizer/fuzz and native-platform qualification remains required before publication.

### Cross-block clock and demux arithmetic regressions

WavPack native admission rejects contradictory effective sampling frequencies across audio blocks before any PCM publication. Metadata-only clock declarations are tracked for subsequent custom-index audio blocks; they cannot hide a rate change applying to actual audio. Shared and FlacCompagnon PCM/spectral regressions preserve the original source.

Musepack's additional local demux patch removes negative signed alignment shifts in SV7 and uses signed 64-bit multiplication for seek residuals, including negative and wide values. The standalone ASan/UBSan reproductions and five independent alignment/seek cases complement the retained word-reader and native PCM regressions. This focused review is not a complete sanitizer/fuzz qualification of libmpcdec.

WavPack predictor arithmetic is compiled separately with explicit signed-wrap semantics where supported, after UBSan reproduced signed add/multiply overflow on corrupt admitted blocks before CRC refusal. The standalone public-API regression retains those inputs and requires defined arithmetic followed by CRC failure; other codecs do not inherit this flag.

The APE dependency receives a read-only seekable view ending at the descriptor's declared audio/terminating-data extent. It can no longer include trailing APEv2 tags in its last compressed frame or let a large cover image inflate that frame beyond its budget. A sparse 65-MiB binary-tag regression compares every decoded chunk against the original reference without modifying source audio.

### Bounded seek fields and fixed PCM representation

Musepack ST admission reads all declared seek fields through a reader capped at that packet's payload. Seek packets are limited to 64 KiB, counts to 65,536 entries, and Golomb residuals to the reference API's signed word. Initial offsets and reconstructed positions must lie inside the opened source; unused bits/bytes must be zero. A truncated table previously passed outer extent/exponent checks and reached an out-of-bounds C Golomb read under ASan. The Rust preflight now rejects it before constructing the foreign decoder, including through SO references. This does not remove the remaining independent C sanitizer/platform qualification.

WavPack admission also keeps channel width, effective PCM precision and integer/float representation consistent across audio blocks. The adapter captures those properties once; a later wider block previously reused the first block's scale and could finish with severely inflated PCM levels. Non-audio blocks and changing compression/prediction flags do not change this source-format contract.

### Effective WavPack clocks

Native admission compares effective sampling frequencies rather than just the four-bit header indices. Bounded metadata framing resolves the three/four-byte `ID_SAMPLE_RATE` field, including odd/large framing, and skips other payloads by checked extents without retaining the audio. Each audio block admits at most 65,536 metadata headers. Conflicting explicit clocks are refused before PCM publication. Equal clocks remain admitted when one block uses a table index and another carries the explicit value; a custom clock omitted in subsequent custom-index blocks inherits the current metadata clock. Leading and intervening metadata-only blocks are included, while clock comparisons apply to actual audio blocks. The initial missing-custom-metadata case retains the reference reader's legacy 44.1-kHz default. Standard header/explicit clock disagreement is an explicit native refusal. The previous index-only check both accepted changing custom clocks and rejected valid equivalent representations. Actual PCM counts and spectral rates have shared/FC/Aède regression coverage.

### Original PCM16 for CUE clients

`native::ApePcm16Decoder` (feature `ape-pcm16`, including `decode`) consumes an already opened regular file. It uses the same bounded descriptor, seek-table and CRC-checked frame reader as normalized playback, returning original signed little-endian PCM16 bytes with no f32 round trip. Exact seeks decode only the containing compressed frame and discard its pre-roll; EOF and any failed visit are explicit. Cloned OS handles share a file cursor, so callers must serialize them. No pathname is reopened.

The admitted bounded profile is APE 3.80–4.10, with mono/stereo, the existing frame/metadata budgets and integer representation restrictions. The file-handle API additionally scans prefixes up to 1 MiB through a bounded buffer and presents APE-relative offsets to the dependency. Phémios narrows this to stereo/44,100 Hz/16-bit and integral 588-frame sectors within 120 minutes. Pre-3.80 versions and profiles outside these budgets remain explicitly unavailable, with no external CUE fallback. The real 3.99 fixture, prefixed variants and every-sample forward/backward/compressed-frame/EOF seeks are software evidence; independent older-version, platform and physical playback acceptance remain pending.

Phémios includes the linked native-codec notices in its future bundle resources. Its source pin must identify the commit containing this API; latest-stable preparation cannot select an older release lacking the `ape-pcm16` feature. Publication and application rebuilds remain separate work.

### Historical APE decoding

The explicitly approved static Monkey's Audio 13.43 SDK (BSD-3-Clause) handles 3.80–3.98; the existing Rust backend remains selected from 3.99. A real 3.97 file reproduced a range-coder failure in `ape-decoder` itself, so merely relaxing its version guard would not restore compatibility. The isolated C++ bridge exposes only an already opened read-only regular-file view, with one SDK decoding thread, caught exceptions and unique ownership. It stages the entire compressed frame's PCM through CRC validation before either normalized or original PCM16 publication. Failed/cancelled visits remain permanently retired.

Historical preflight validates the 32-byte header, optional peak/seek counts, stored wrapper, byte/bit seek tables, actual frame sizes and trailing APEv1/v2/ID3v1 extents before SDK allocation. The same 4-MiB seek-table, 1-MiB wrapper, 16-MiB compressed-frame and 1,048,576-scalar decoded-frame budgets apply. Trailing tag payloads are skipped by extent; no whole-file audio/tag buffer is created. Automatic content probing also recognizes bounded leading ID3 tags plus padding without scanning unrelated codec payloads; the explicit CUE file-handle API retains its bounded general prefix support.

Checked-in synthetic 3.95/3.97 vectors exercise full-frame CRC, exact seeks, optional wrappers/tags, invalid extents, cancellation and source retention. Independent local every-sample/seek acceptance covers real 3.97 and complete historical FATE excerpts from 3.80/3.88/3.89/3.91/3.92/3.94. Exact provenance and the repeatable comparison example are in the shared fixture README. This is historical stereo PCM16 software evidence, not exhaustive compression-level/precision/Windows/Linux/musl or hardware qualification. No product App, embedded engine or frontend bundle is rebuilt by this source integration.
