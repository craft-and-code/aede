# Shared audio foundation

For a bilingual component overview of the three applications, see the [shared architecture guide](../manual/ecosystem.md).

The [audio format matrix](audio-format-matrix.md) inventories native and external decoding in all three applications, with the remaining replacement order and qualification corpus. It distinguishes catalogue recognition, listening, original-integer analysis and spectral rendering; sharing the DSP does not by itself supply a decoder for every format.

`crates/aede-audio` is the catalogue-independent PCM foundation used by Aède, Phémios and FlacCompagnon. It reuses `aede-dsp`; it does not introduce another DSP implementation or depend on an application, an analysis engine, a catalogue, an account, HTTP or Tauri.

## Feature boundaries

- No default features or default device/network activity.
- `decode`: progressive local-file Symphonia reader extracted from FlacCompagnon's preview path, with finite complete-frame validation, bounded packets and admission between packet reads. This feature does not pull in the DSP or device backend. Native DSF/DFF input adds separate measurement and listening profiles; see [native DSD](native-dsd.md) for the admitted formats, bounded filters and unpublished integration boundary. Application-specific verified FLAC, Vorbis and external-codec paths remain in Aède.
- `dsp`: access to the existing `aede-dsp` numerical implementation and shared PCM format contracts. Loudness capture/meters are a separate, default-enabled feature of `aede-dsp`, disabled for the minimal player.
- `queue`: Aède's complete-frame bounded single-producer handoff, including its original sibling regression suite, plus Phémios's existing callback transition/reserve policy and the underlying ring types. Queue metadata describes precision; it supplies no bit-perfect device guarantee.
- `output`: optional CPAL single-file `MinimalPlayer`, progressive decoding and the shared bounded queue. It opens no device until explicitly requested, starts paused and has no catalogue, history, normalization, EQ, crossfade or strict-output control.
- `dop-alsa`: opts into the direct ALSA hardware backend with the existing 0.11.0 bindings, including custom musl builds with target libasound. Linux GNU CLI builds select it; the default static musl artifact does not.
- `dop-output`: optional original-DSD player with dedicated CoreAudio HAL and WASAPI exclusive/raw output, using `decode`/`queue` without pulling CPAL. `output` also enables this independent API. Explicit DoP-compatible DAC selection, preservation/refusal contracts and the initial CLI integration are defined in [DoP output](dop-output.md); the ordinary minimal player remains PCM.

The minimal player adapts channels and sample rate only as required by the device, using the existing downmixer and bandlimited streaming converter. Same-format PCM is unchanged until device volume and the final output guard. Its ring holds half a second, decoder packets are bounded to 1,048,576 samples, and resampling retains its existing bounded working blocks. It does not retain a track-sized PCM buffer. Control-thread polling publishes device-consumed time and distinguishes real EOF from errors. The audio callback does no allocation, locking, UI emission or logging.

The shared decoder checks regular-file admission before opening and on the opened descriptor. Native FLAC playback reuses the same metadata-free source view as Aède's verified decoder: only STREAMINFO and original encoded audio reach the demuxer. Optional FLAC metadata bodies are skipped using checked container extents, including when probing locates the FLAC marker after unrelated prefix bytes. Contiguous leading ID3 bodies are also skipped when followed by native FLAC. Each leading-ID3 or FLAC metadata traversal is limited to 65,536 headers. Audio files and tags remain unchanged. This bounds the shared native-FLAC metadata path, not every allocation made by every codec or the whole process.

Unexpected unwinding panics from the pinned probe or codec become decoding errors. A reader or codec that panics during progressive decoding is retired permanently; subsequent reads cannot publish stale PCM or successful EOF. Caller admission callbacks keep their own error/panic behavior. Downstream builds using `panic=abort` cannot recover through this boundary, and an already running OS read is not forcibly interrupted. I24 output saturates positive full scale to the largest valid signed 24-bit value; floating output and the other device representations retain their existing conversion behavior.

Pause consumes no source frames; mute retains volume. Seek explicitly reopens the decoder and progressively discards a cancellable source prefix, preserving pause/gain. It is not constant-time seeking or gapless output. The optional admitted open/seek APIs recheck the captured owner between preparation stages and before replacing/resuming a prepared stream. A retired prepared value is dropped rather than published; callers with account or playback-generation ownership must supply this admission. Replacement also rechecks admission after dropping/joining the old visit and before resuming the prepared output, since retirement itself can wait for a file read. A cancelled replacement stays paused. Stop/seek joins the retired decoder worker to prevent worker accumulation and can wait for one regular-file read already in progress. Packet admission checks cancellation even when corrupt/non-audio packets are skipped. No forced interruption of OS filesystem I/O is claimed.

## Candidate native Opus input

The `decode` feature now includes ISC-licensed `audiopus` 0.2.0 and its `audiopus_sys` 0.1.8 companion, already used by FlacCompagnon's encoder. The static-link feature avoids a runtime Opus shared-library requirement; no FFmpeg executable is invoked. Native build environments need the C/autotools prerequisites recorded in CI (GNU libtool on macOS). This is an unpublished candidate under the same coordinated-source release boundary as DSD.

`decode::make_decoder` is the common codec factory for the progressive reader and FlacCompagnon's original analysis/spectrogram visitor. Other codecs retain the pinned Symphonia registry. The first Opus profile admits complete, known-length, mapping-family-zero mono/stereo streams at 48 kHz. The OpusHead input-rate field is informational; the normative header output gain is applied once by libopus. Pre-skip is removed once, even across packets, and final granule bounds also handle a single audio page whose demuxer omits per-packet end trimming. Source bytes remain unchanged.

Opus PCM is bounded to one 120-ms packet (5,760 frames per channel), with a 61,440-byte compressed-packet limit and bounded planar/interleaved scratch buffers. No application volume, normalization, EQ or crossfade is applied here. The safe wrapper is Send-only; a worker-owned Mutex supplies the public codec trait's Sync requirement, without any audio-callback lock. No new unsafe Rust is introduced. The decoder clears output and retires after corrupt packets; completion verifies the exact playable-frame count. Preview/spectral admission remains checked around packet work and publication; a running libopus call cannot be forcibly interrupted. A retired shared Opus visit cannot resume buffered audio.

Seek reopens and progressively decodes pre-roll through the existing player. Cold midstream codec reset is explicitly refused rather than applying pre-skip again at the wrong point. Chained/multiplexed, unknown-length, nonzero-origin and multistream layouts are outside this initial native profile. Aède retains explicit compatibility decoding when opening an unsupported Opus profile; FlacCompagnon explains its native boundary instead of claiming every Opus stream is supported. This does not remove the other compatibility codecs in the [global matrix](audio-format-matrix.md).

The original generated mono, stereo and very-short fixtures exercise exact frame count, multi-packet pre-skip, input-rate/header-gain behavior, stereo order, corrupt/truncated input, reset and cancellation. Aède adds native-only seek and a resolver-spy spectral test; FC adds full-analysis/PNG-input and encoder round trips. The encoder must submit the algorithmic tail and keep non-final granules in raw decoded-frame units; only the last granule includes the exact source length plus pre-skip. Native platform builds/listening remain separate acceptance.

## Candidate ALAC configuration admission

`decode::codec_parameters` supplies ALAC clock, speaker layout and integer precision when an incomplete MP4 sample entry omits the channel layout. It reads the standard 24-byte codec configuration (with validated optional 24-byte Apple layout information) described in [Apple's format documentation](https://raw.githubusercontent.com/macosforge/alac/master/ALACMagicCookieDescription.txt). It keeps the original cookie and frame/timeline hints unchanged. A high-rate cookie takes precedence over MP4's possible 48 kHz placeholder. ALAC cookies are validated even when the container already declares channels; declared speaker roles must match the validated cookie layout. The cookie supplies precision and the authoritative clock, including incomplete or placeholder container hints. Other codecs retain their prior parameters. Explicit Apple layouts admit three through eight channels; above stereo the optional layout must be present and agree with the count. Unspecified discrete or legacy configurations are not guessed; existing compatibility paths remain available where previously provided. This is header/configuration admission, reusing the existing Symphonia ALAC decoder, not another codec implementation.

Configuration lengths, version, precision, positive clock/channel/frame values and the shared per-packet PCM budget are checked before native initialization. Original independently encoded ALAC16 mono/44.1 kHz and ALAC24 stereo/96 kHz fixtures exercise every sample and active low bits, exact tails, truncation, native seek/cancellation and full-analysis precision/duration. Native spectral tests refuse any external resolver call. Original PCM16 references additionally qualify every explicit Apple layout from three through eight channels, including each speaker and exact native seek. The FC probe uses this same shared function for playback-independent analysis and captions; no local parser is added there.

The metadata-only `read_alac_configuration` inspector also supplies Aède's existing MP4 tag reader. Header inspection remains separate from native admission: a partial or multichannel cookie can expose available catalogue properties without promising that the decoder admits it. Both paths therefore share field interpretation while preserving metadata browsing for unqualified profiles.

ALAC packet failures are fatal in progressive playback; they cannot silently remove a damaged packet and turn a shortened source into successful EOF. `declared_pcm_frames` distinguishes media ticks from decoded frames, retaining an exact completion count only when the media clock resolves whole PCM frames without rounding. Coarser clocks remain duration hints rather than exact PCM bounds. The shared factory independently checks ALAC packet coverage in container ticks, including at finalization, so a missing tail cannot become successful EOF when a rounded clock provides no exact PCM count. Each decoded packet must also agree with its own media duration: an exact sample clock allows no frame discrepancy, while a rounded clock allows at most one media tick of quantization. Integer cross-products avoid floating-point rounding and overflow. A present but shorter decoded packet is refused before PCM publication. ALAC callers must reject a false finalization result; this checks completion rather than a source checksum. Reset restarts coverage only for a codec that has not failed. Full ALAC analysis reports counted PCM duration. A retired shared ALAC visit cannot resume old buffered audio after cancellation or failure.

The shared codec factory guards unexpected decoder unwinding for all its codecs. A panic retires that codec permanently, exposes no last decoded buffer and cannot be cleared by Reset; the caller must create a new codec. Construction, reset and finalization also convert unexpected unwinding to failure. This guard runs on decoding/control workers, keeps original integer buffers and does not introduce per-frame allocation or audio processing. It is not a claim that every altered ALAC bit is detectable without a source checksum.

Spectral compatibility is selected for configurations the native reader cannot open. After successful ALAC admission, a later native data failure returns an error instead of asking an external decoder to recover a shorter prefix. Existing images are preserved on failure; generation v4 marks images from before the ALAC packet-duration checks stale. The six-channel reference exercises metadata inspection and retained compatibility only, without admitting native multichannel playback.

The ALAC candidate does not certify all rates/layouts/platforms. It remains unpublished under the existing coordinated release boundary. AAC uses the separate admission below.

## Candidate AAC-LC MP4 input

The shared `probe_file` admits a bounded AAC-LC mono/stereo MP4 profile using the existing Symphonia decoder, not a second AAC implementation. `read_aac_lc_configuration` supplies known LC frequency/layout to metadata readers without requiring decoder admission. No source PCM bit depth is invented for this lossy codec. The AudioSpecificConfig must identify the 1024-frame LC profile, without an enabled SBR/PS/core-coder dependency or an unknown extension. Explicit HE profiles and PCE/multichannel/960-frame layouts are outside this admission; implicit signalling is not a promise of HE compatibility.

The initial MP4 profile requires one audio track, a reciprocal PCM media clock, contiguous sample timing and one positive, normal-speed full-track edit. Its media start supplies the actual encoder delay; no fixed 1024/2112-frame priming value is assumed. Complete compressed packets still reach the codec for predictive pre-roll. An adapter marks their playable interval, then the codec wrapper removes only the declared leading/trailing PCM. Movie-clock rounding is accepted strictly within one tick only when a short final STTS delta provides an unambiguous source end and that end is not exactly representable in movie time. A different sample-accurate edit is a real crop/extension and is refused by the full-track native profile; it cannot be rounded back to the original duration. An exact movie-clock interval can also admit an aligned final packet. Missing, empty, multiple, speed-changing or ambiguous edits retain the existing optional Aède compatibility route instead of guessing iTunSMPB timing. Other container/profile support is unchanged; the ordinary ADTS LC fixture retains its coded duration because it carries no such original-length edit.

Metadata traversal seeks over encoded audio/artwork, budgets 65,536 box headers and reads at most 32,776 bytes per header/table. It uses the already-open file identity and restores the shared descriptor cursor before buffered packet reads resume. PCM remains bounded per packet. The selected packet count, timestamps, frame lengths and final tail are checked; missing packets and detected decoding errors cannot become a shorter successful decode. This is structural completion validation, not an audio checksum. AAC cancellation uses the existing admission checks around reads/codec calls and retires a cancelled preview. Existing operating-system reads and codec calls are not forcibly interrupted.

Aède playback and FC analysis/spectral visitors use this same probe and codec factory. Successful AAC admission prevents a later spectral data error from starting an external recovery; image publication remains atomic and generation `aac-edit-v2` invalidates older results. Synthetic mono/44.1 kHz, stereo/48 and 96 kHz, short, rounded-movie-clock and longer-than-buffer sources exercise independent-decoder PCM comparison, exact playable duration, seeks, cancellation and truncated tails. These are qualified fixtures, not blanket certification of every AAC encoder/profile or physical platform output. The candidate APIs still require coordinated publication before standard client builds can consume them.

Priming/edit semantics follow [Apple's AAC timing documentation](https://developer.apple.com/documentation/quicktime-file-format/background_aac_encoding), [edit lists](https://developer.apple.com/documentation/quicktime-file-format/playing_with_edit_lists) and the ISO-BMFF sample timeline; the public packet API is [Symphonia 0.5.5](https://docs.rs/symphonia-core/0.5.5/symphonia_core/formats/struct.Packet.html).

## Application ownership

Aède core uses the shared ordinary progressive decoder and PCM formats; its CLI uses the shared handoff. Aède retains verified/exact decoding, rich processing sessions, strict ALSA negotiation, fallback output, history, supervision and the authenticated PCM protocol.

Phémios retains authenticated stream ownership, preloading, per-occurrence accounting, device/UI metering and its continuous output callback. Its transition/reserve policy and ring now come from `aede-audio`; crossfade sample mathematics comes from `aede-dsp::mix`. It continues receiving Aède-processed PCM, without applying normalization a second time. Local CD transport remains independent of an Aède login.

FlacCompagnon's progressive preview decoder is a compatibility adapter to `aede-audio::decode`. Its Tauri player is a command/event adapter to `MinimalPlayer`; no Aède server or account is required. Its analysis decoder and original-integer measurements remain separate and are not normalized or resampled by preview playback. The existing whole-file conversion helper remains available for explicit analysis/conversion workflows, never for the minimal player.

## Source and release integration

Aède keeps ordinary workspace path dependencies between crates in this repository; those paths are contained in a single checkout. Phémios and FlacCompagnon declare `aede-audio` once in `[workspace.dependencies]`. Their native development/build entry points automatically query the official latest **published stable Aède release**, resolve its version tag to an exact commit, update the shared dependency and Cargo lockfile, and fetch dependencies before compilation. The selected full SHA remains in the generated manifest/lockfile for that build; `aede-dsp` resolves from the same source. No adjacent checkout, development branch, draft, prerelease or automatic fallback to an older revision is used.

Each GitHub workflow selects the release once in an `audio-source` job, then passes its tag/version/SHA to all compilation jobs through `AEDE_AUDIO_RELEASE`. A release appearing while a workflow is running cannot split its platform builds across revisions. Phémios compiles its bundled engine from that same clean cached source, retaining `cargo build --locked --offline` after the explicit fetch. Arbitrary engine binary/source overrides and old executable caches cannot bypass selection. FlacCompagnon's native hooks and its `npm run build:cli` entry point prepare the shared source before compilation while retaining its minimal playback feature profile.

Publish a stable Aède release to make a shared DSP evolution available to the next client build; manually editing both clients' SHA is no longer required. The checked-in revision remains the last selected baseline for direct Cargo checks, not a promise that a future build uses it. Raw Cargo commands alone consume the existing lock; run the client's preparation entry point first when invoking Cargo directly. New workflow runs, including reruns of an old App tag, deliberately select the then-latest stable Aède release and can therefore differ from a previous run. Build logs and `.audio-source/selection.json` record the selected revision.

Native build preparation requires network access to verify the latest release. Network/provider errors, moved tags, edited cached sources, incompatible source versions and releases without the shared crates fail explicitly. Source/dependency preparation does not compile an App. A failed dependency fetch restores the prior manifest and lock unless another writer changed them; concurrent edits are preserved and reported for review. `.audio-source/` is disposable build data and is not committed. The initial technical tag `audio-core-d8c0f1a8` remains a retrievable bootstrap source but is not an automatic-update candidate. Published Aède `v0.6.1` predates this extraction: the next stable Aède release must include `aede-audio` before automatic client builds can proceed. Library and dependency checks do not certify native platform execution.

## Aligned development source graph

Locked development verification uses one reviewed `aede-audio`/`aede-dsp` anchor, recorded by full revision in their manifests and lockfiles, in both FlacCompagnon and Phémios. Aède then pins the compatible FlacCompagnon analysis/spectrogram commit by full revision. That order breaks the repository-level dependency cycle: the audio anchor precedes FlacCompagnon's consumer commit, which precedes Aède's analysis consumer. These package sources can have different repository HEADs while sharing byte-identical audio code. Exact identities live in each Cargo manifest and lock; no sibling source path or invented stable tag is committed. Aède patches its own Git-source audio/DSP packages to the crates inside the same checkout, so the FlacCompagnon dependency uses the actual workspace decoder and only one native backend is linked. External clients keep their immutable Git anchor.

Direct source checks retain these reviewed pins. Normal latest-stable preparation remains an explicit separate policy and requires compatible published releases; it is not run during source-only verification. Aède's update helper can replace a reviewed full revision with the next selected published tag, preserving its rollback and unrelated-dependency guarantees. Local commits are not publication evidence.

## Verification without rebuilding Apps

Run `bash tools/check.sh --sources-only` in any of the three repositories. This fail-closed mode uses locked sources, tests/lints/documents the non-App Rust packages, and runs the applicable frontend behavior/type, fixture, helper and documentation checks. It does not resolve a different dependency, compile a product App, generate a frontend bundle, rebuild Phémios's embedded engine, or certify an existing binary against changed sources. Command-recorder regressions preserve that boundary and stop the mode on test failure. Full product/packaging gates retain their independent requirements.

Run `cargo test -p aede-audio --all-features --locked --offline`, the existing Aède playback tests and the Phémios core tests. The extracted queue/format tests keep their original behavior and count. FlacCompagnon core's `native_preview` harness compiles the actual thin adapter with an inert event sink, without Tauri. Required real encoded-file fixtures remain in each application's existing suites. Library tests, Clippy and Rustdoc do not establish native App execution, other-platform compatibility, physical output fidelity or listening acceptance.

Check feature isolation as well: `cargo test -p aede-audio --no-default-features --locked --offline`, the same command with `--features decode`, and `cargo test -p aede-dsp --no-default-features --locked --offline`. Run Clippy with `--all-targets` for both the minimal and full profiles. The DSP profiling example and loudness-only test fixtures require the `loudness` feature; ordinary device playback does not enable it.

## Additional native spectral inputs

The candidate shared reader adds WavPack, Musepack, Speex and APE through approved isolated static reference libraries and `ape-decoder`. Aède and FlacCompagnon reuse it for Rust spectrograms; no decoder is copied into either spectral engine. See [profiles, timing, budgets, FFI and release boundaries](native-additional-codecs.md). ## Native surround follow-up

The existing static libopus now also decodes RFC 7845 mapping family one, with one through eight named speakers. The explicitly approved owned FFI adapter validates stream/coupled counts, all mapping indices and the exact PCM output capacity. It reorders the mapping into canonical speaker-mask order before native creation, including duplicate channels and index-255 silence. Every C call is confined to `decode_opus_native.rs`; the state has one owner, exclusive calls and one destructor. No new dependency or second libopus build is introduced.

Native tests qualify all eight layouts using original distinct-speaker tones, exact non-packet-aligned duration, header gain, multi-packet pre-skip, reset, packet-error retirement, truncated tails, cancellation and output-buffer sentinels. Complete known-length gapless demuxing and progressive seek pre-roll remain required. Unspecified/ambisonic mappings, chained streams and unknown length do not gain an invented speaker order or completion guarantee. See [RFC 7845](https://www.rfc-editor.org/rfc/rfc7845.html#section-5.1.1).

This removes the external decoder requirement for the newly qualified Opus and explicit ALAC surround profiles. It does not remove all optional compatibility paths: non-LC AAC needs another qualified codec; FLAC 33-bit side channels, broader DSD profiles, other container edits/mappings and native musl CLI output remain separate work. Native Windows/Linux execution and physical audio acceptance remain distinct from host source verification.

## Decoder reference review (2026-10-28)

The review compared the admitted profiles with Sony DSF 1.01, Philips DSDIFF 1.5, DoP 1.1, Apple's ALAC cookie/CAF specifications, the WavPack 5 library contract and the pinned Speex/Musepack/Monkey's Audio reference libraries. Three original regressions demonstrated and corrected floating WavPack exponent scaling, ALAC hints bypassing cookie/layout/budget validation, and an explicitly terminated partial final Speex packet. Fixture generators and reference provenance live beside the audio fixtures. Float exponent adaptation maps the format to the common PCM domain; it does not apply playback or loudness gain.

FlacCompagnon records an optional decoder provenance in each report row. Older reports remain readable; affected floating WavPack and multichannel ALAC measurements require decoding again before automatic reuse. Aède also versions PCM-derived spectrogram, waveform, loudness and acoustic-descriptor caches. Human annotations and retained reports are preserved; descriptor definitions and the mood PROFILE are unchanged. Imported projections lacking sufficient codec identity cannot provide fresh playback gain until measured again.

This is software evidence for the listed profiles, not universal codec conformance or physical bit-perfect output. Speex retains coded frame padding and is not qualified for original sample-exact gapless joins. WavPack hybrid without its correction file remains lossy. Additional AAC encoders, ALAC precisions/CAF layouts, Musepack SV7 reference material and APE precisions/compression modes still need independent qualification. DSD PCM requires integrated noise/alias/THD+N measurements with independent modulators; DoP needs named DAC/driver capture and native Windows/Linux execution. See the [format matrix](audio-format-matrix.md) and [DoP acceptance](dop-output.md).
