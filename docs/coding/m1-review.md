# M1 identification, enrichment and source safeguards

M1 keeps provider claims and provenance separate from local file facts. This is a domain summary of retained corrections, not a chronological pass log. See [sources](../sources.md), [roadmap](../design/roadmap.md), [manual verification](m1-manual-verification.md) and [current state](current-state.md).

## Trust, namespaces and identity

Accepted/identified source evidence is projected consistently across queries, detail pages, country/role selectors, canonical works and continuation links. All trusted observations participate before deduplication; a pending/rejected first observation cannot conceal a later trusted one. Review duplicates cannot make trust depend on input order. Accepted approximate evidence retains its original matched score/decision rather than being displayed as identified.

Edition MBIDs and release-group MBIDs are different namespaces. A no-group edition fallback is not an invented conflict with a known group. Source URLs select their real entity kind; an AcoustID observation storing a MusicBrainz recording MBID cannot become an AcoustID-track URL. Exact local references remain usable when an MBID alias is ambiguous; homonyms are not collapsed merely by name.

Do not enforce equality between a queried and returned MusicBrainz MBID: [merged identifiers may redirect to a surviving identifier](https://musicbrainz.org/doc/MusicBrainz_Identifier). A changed canonical ID alone is not a demonstrated unrelated response. Artist/recording source resolution, missing-album identity comparison and credited-person navigation retain this distinction.

An artist lookup following that redirect retains a discography cached for the queried identifier, including a completed empty browse. A different name-search result or a prior claim unrelated to the queried identifier does not inherit that discography.

An exact artist lookup also retains its verified `lookup_mbid` alias alongside the canonical source ID. Completed recording lookups use their captured `relationships_for` only when the retained canonical recording agrees with that source ID. The local tag can match the verified alias or the canonical ID without creating a false conflict; unrelated local IDs still conflict, and name-search scores never become identifier certainty. Acceptance and rejection follow a verified continuation of the same identity, including successive merges, while a genuinely different match loses the old decision. Secondary biography-link completion preserves artist alias evidence. An explicit refresh of the same canonical recording retains its earlier verified alias, without inheriting another identity's evidence. Legacy snapshots without it remain conservative until a successful explicit refresh supplies the proof.

Label lookups retain the canonical source ID and a verified optional `lookup_mbid`, like artist and release-group lookups. This covers direct identification and exact completion of a name-search result: the latter keeps its original match confidence and cannot become trusted without a decision. Both a retained local alias and a later retag to the canonical ID remain usable after cache reload, including typed label navigation. Acceptance/rejection follows a verified continuation; unrelated identities inherit neither proof nor decisions.

Secondary artist-biography and label-Discogs completion follow the same rule instead of discarding a returned canonical ID. Requests prefer a current local identifier only when the claim has already confirmed it; otherwise they reuse a verified alias or the source selector. This retains existing tag evidence through successive merges without following a contradicting local tag. Completing these links preserves the original confidence, current decision and artist discography. Legacy snapshots without optional proof remain readable and conservative until successfully refreshed.

Direct release-group lookups keep their canonical source ID and an optional verified `lookup_mbid` in release facts, like artist lookups. Both the queried alias and a later retag to that canonical ID stay usable after reloading the cache; acceptance/rejection follows only a verified continuation. Only querying the group itself establishes its alias: an edition lookup cannot turn its edition selector into a group identifier, and subsequent edition completion preserves prior group evidence only for the same canonical group. Name searches retain their candidate scores and do not inherit unrelated decisions.

Exact edition lookups retain the canonical edition and a separate optional `edition_lookup_mbid` for its verified queried alias, both during ordinary fetching and credit completion. Cache reload, retagging to the canonical edition and explicit refresh keep the credits and acceptance/rejection usable for both confirmed identifiers. A different edition of the same group does not inherit them, and an edition alias cannot establish a group identity. An answer without a release group remains a canonical edition fallback in both its identity fields. Legacy snapshots without alias evidence remain readable and conservative until refreshed.

Missing-album comparison recognizes both sides of a trusted verified group redirect only when the associated local release still carries one of those group IDs. This applies before and after retagging, across artist shelves. Rejected/pending claims, edition fallbacks, detached records and conflicting local tags do not supply group equivalence; existing literal tag identities and per-artist title fallback remain unchanged.

## Credits and personal corrections

Canonical recording/work and parent-work evidence reaches every exact supported placement, not only the file that supplied one observation. Role filters include trusted source contributions alongside local graph credits; distinct performers do not collapse under one display name. Uncertain membership dates remain explicitly counted rather than silently hidden or claimed as performance evidence.

Manual credits retain their selected recording/edition target through later identification or representative changes. Adding a new credit cannot move older claims to another edition, and changing an observation cannot duplicate the same assertion. Personal contexts/exclusions survive canonicalization into a local artist without widening to ambiguous identities. A direct recording correction never follows a later recording occupying the same file path.

## Provider admission and retry semantics

Malformed supplied arrays, nested targets, facts containers and completion markers are refused; unreadable answers are not successful empty results or permanent cached absences. This applies to MusicBrainz relationships, Wikidata portraits, Wikimedia prose and Fanart tables. Unicode dates are validated without unsafe byte slicing. Completion for one canonical recording is not restricted to only one placement.

Artist, label and release-group candidates must carry a valid MusicBrainz UUID before ranking, issuing an identifier lookup or replacing a stored claim, including during ordinary identification and refreshes. Supplied release groups inside edition answers require the same readable identity; an absent/null group still permits the established edition fallback. Malformed candidates cannot hide a lower-ranked valid match; an unusable response retains the prior facts and reviews and remains retryable. A different valid UUID from a lookup can be a merged identity and is not refused solely for differing from the requested one.

Secondary fetches preserve accepted identification, source trust and exact scope. Existing artwork/lyrics is established from current confined regular files, not remembered catalogue hints alone. Removed sidecars become eligible again; published covers/logos/portraits do not trigger redundant alternate downloads while catalogue metadata catches up. LRC metadata alone does not establish readable words.

Artwork lookup receipts, including empty answers and legacy family-completion markers, apply only to their captured artist, label or release-group identity. A corrected MusicBrainz identity reopens the corresponding lookup without forcing unchanged identities to repeat requests or overwriting images already present. Fanart.tv image entries require a readable address, and album entries require their release-group selector; malformed entries retain the prior answer and remain retryable instead of establishing a completed absence.

Wikidata portrait receipts capture the queried Wikidata entity, independently of the artist's MusicBrainz ID. Correcting that relationship reopens the portrait lookup; legacy receipts that only captured the MusicBrainz ID are confirmed once when no image is already present. Recording-credit receipts likewise retain the queried ID separately from a returned canonical ID: a local identity correction reopens the lookup, while the captured alias, its confirmed canonical ID and other placements of the same recording reuse its completed answer. Reuse admits an alias through the same completed, consistent canonical proof as source trust; an imported receipt with missing or contradictory canonical recording facts cannot suppress that alias's lookup. A contradiction between a present source ID and recording fact also prevents reuse under the principal ID. Consistent legacy snapshots carrying only one selector keep their existing principal-ID receipt, without inventing alias proof. Credit-coverage reads use that same coherent identity: an internally contradictory snapshot neither completes coverage nor outranks a valid snapshot on another placement. A legacy recording fact without a source ID still supplies its declared identity for local conflict checks and for retaining an explicit decision through a verified refresh or redirect.

Missing-artwork cache identities cannot escape the cache. Native artwork rechecks initially anonymous access when authenticated mode becomes active. Phémios missing-cover requests reuse their authenticated session agent and exact TLS identity, just like ordinary artwork; neither default trust nor an insecure verifier is substituted.

Fingerprint backends describe the complete requested input: fallback fpcalc cannot silently stop at its default two-minute prefix while retaining full duration. Default identification honors explicit plural artist tags before deciding acoustic rescue is necessary; full/scoped acoustic requests remain explicit choices.

## CLI and retained exports

Human/machine windows apply consistently to source-only subsidiary lists and source-backed facets. Unsupported combinations, admitted-but-unused source options and conflicting fetch/logo operations are refused. Literal artist/title hints use the central shell quoting policy, while unstyled prose, source IDs, relations and notes use terminal escaping. Source and local names are never executable command fragments.

Export equivalence compares graph content independently of its legitimate `exported_at` timestamp. Test fixtures do not depend on two commands completing within one civil-clock second. Attribution, confidence and licensing remain intact in all source projections.

## Verification boundaries

Behavioral tests preserve offline source/import/review flows, canned malformed provider responses, exact source identity and public CLI results. The [manual procedure](m1-manual-verification.md) distinguishes live-source observations from fixtures. Provider availability, source correctness, licence compliance and changed upstream schemas still require operational attention; offline checks do not certify every live response. No browse should silently fetch enrichment or overwrite audio/tags. Detailed regressions and before/after evidence remain in tests/Git rather than repeated status paragraphs.
