## Scope and evidence

The review follows supported producer/consumer chains, rather than treating arbitrary hand-built graph states as reachable failures:

- M0 scan/cache/rebuild → sidecar analysis import and reconciliation → independent conclusions → server catalog reload and track inspection/export.
- M1 source enrichment and accepted identity aliases → canonical catalog navigation → owner-private annotation read/update and reconciliation.
- M2 shared writer boundaries and CLI administrative jobs → catalog publication, retained source reads and private data consumers.

Additional inspection covers startup loading under the writer lock, native analysis reloading after long decoding, `scan::import_reports`, `analysis::{merge_into, reconcile}`, report export source-entry retention, `runtime::{stamp, refresh_catalog}`, `personal::{canonical_target, locked_personal_full}`, source trust/origin selection, job argument termination and secret handling. No further demonstrated defect is retained in those adjacent paths. This is finite source coverage, not a claim that every function or platform has been exercised.

## Demonstrated cases and corrections

There are three failure families, with two independent date-association cases in the second family:

| Case | Source evidence before correction | Correction |
| --- | --- | --- |
| Imported bit depth wraps | The external-report mapper reads a `u32` then casts with `as u16`: `65552` becomes `16`. The false measurement can be attached by a scan, persisted and returned by track details, despite the already corrected stored-field reader. | Checked conversion refuses malformed or overflowing present values. Missing/null measurements, representable values and unknown fields remain compatible. |
| Reused analysis receives another report's date | The native cache stores payloads separately from `saved_dates[path]`. Every later report for that path overwrites the date, including a stale or failed entry which `reusable` rejects. An older valid payload can consequently be assigned a newer unusable report's date and replace a newer retained measurement. | Keep each cached payload with its own date, sort by measurement date, then select the newest reusable entry and its date together. |
| Report rewrite promotes old results | `analyze --json` combines reused and newly decoded entries, then writes a report with a fresh file mtime. `analysis::read_report` previously assigned that mtime to every entry. A reused older measurement initially skipped by `merge_into` can therefore replace the newer retained result on the next scan/import. | Aède-written entries carry the additive exact decimal string `aede_result_at_ns`. Reuse, import and scan preserve it, including explicit zero. Ordinary upstream reports retain their existing file-mtime fallback. The independent conclusions date format remains unchanged. |
| Analysis output bypasses terminal escaping | `show_result` and progress/reuse/folder/failure prints directly interpolate report text and filenames. Imported cache fields accept JSON strings containing ESC/OSC/BEL/carriage-return controls, and Unix filenames can contain terminal controls. The existing `ui::literal` guard is not applied at these output sites; main's guarded error output does not guard successful progress/results. | Human analysis output reuses `ui::literal` for untrusted strings. Pure result/progress formatters make the displayed behavior observable in a sibling regression. Retained source text and machine reports keep their original values. |

The date extension is written with the existing `serde_json` dependency after upstream float stabilization, retaining integer precision. File replacement uses the same upstream `write_atomic_bytes` primitive as `write_json`; destination checks, atomic replacement and source-audio policy remain unchanged. The extension is backward compatible for readers which ignore unknown fields. Another tool or an earlier Aède that discards/ignores it cannot preserve this per-entry date contract; ordinary report-mtime behavior then applies. No new dependency, unsafe code, account permission, provider request or catalog format is introduced.

Three additional cases are established from supported producer/consumer calls:

| Case | Source evidence | Correction |
| --- | --- | --- |
| A downloaded legacy report acquires a new measurement date | `analysis::export::report` clones `source_data` without the conclusion's `result_at_ns`. A legacy imported entry lacks `aede_result_at_ns`, so `read_report`/`parse_report_at` uses the downloaded file's date. Exporting result T1, subsequently retaining result T2, then importing the download with file date T3 (T1 < T2 < T3) replaces T2 with T1. The preceding native-report correction does not cover this response builder. | Add or normalize the exact per-entry date in the response, using the retained conclusion, including explicit zero for unknown. Stored source data remains unchanged. Entry size is checked before cloning and the final bounded renderer includes the added metadata. |
| Cache reuse discards unknown measurements | Native `analyze` reads cache files into `fc::FolderReport`, then rebuilds JSON from those typed fields. Serde ignores unknown fields; rebuilding drops them, including unknown nested measurement fields. Core import initially retains them in `source_data`, but an equal-date cache-only run can replace that complete entry with the reduced projection even without decoding or writing another sidecar. A mixed cache/new run also writes the reduced entry to disk. | `acoustic::saved_report` retains each typed projection, its own validated date and its full raw JSON entry. Shared immutable source entries use `Arc`; the native report writer uses the complete original entry for selected cache hits and changes only the date metadata. Fresh results keep upstream float stabilization, and raw integer fields retain their JSON integer precision in reports. |
| A partial report suppresses a complete native analysis | The pinned upstream `FileAnalysis::analyses_run` explicitly records partial measurements, and `covers_selection` distinguishes them from complete/legacy results. Native `analyze_file` requests `AnalysisSelection::all`, but Aède's `reusable` checks only error/path/size/mtime. A valid MD5-only report therefore skips the requested acoustic work and remains partial. | Reuse the upstream `covers_selection(all())` guard. Partial or unknown explicit coverage triggers analysis; absent legacy coverage and explicit full coverage remain reusable. Partial reports remain valid for import, inspection and download; coverage views are not redefined to invent missing measurements. |

Three new sibling regressions are prepared, not executed: `export_tests::downloaded_reports_keep_legacy_measurement_dates_when_imported_again`, `analyze_tests::reused_measurements_keep_unknown_source_fields_in_the_store_and_rewritten_report`, and `analyze_tests::partial_reports_do_not_suppress_a_requested_complete_analysis`. The previous acoustic serialization regression additionally checks complete raw-entry reuse, nested unknown fields and a large integer. The two existing exact-entry export expectations add only the newly required date metadata; complete source-field equality, album order, unknown fields, selection and count assertions remain. No existing test declaration is removed or disabled. Verified test counts remain unchanged.

The correction reuses the pinned upstream selection API and existing serde dependencies. No package/version, persistent format, account permission, original audio or tag is changed. The public report envelope and bounded HTTP admission remain unchanged; response metadata and bilingual guidance are synchronized. ## Third interaction pass, 2026-10-18

Two failure families are retained, with two distinct cache-transition cases:

| Case | Demonstrated source ordering | Correction |
| --- | --- | --- |
| A cache invalidation silently omits a selected file | `pending` is fixed before decoding. After another file decodes, a previously reusable file is checked again. If it was removed or changed meanwhile, it belongs neither to the decoded subset nor to the appended cache hits. The command previously returned success, and JSON output could replace an existing report with only the other files. | Count/report invalidated cached selections, preserve completed measurements, finish with failure and skip creation/replacement of that album's incomplete sidecar. |
| A cache becoming valid again duplicates and overrides a fresh result | A file rejected from cache enters `pending`. If its original mtime is restored before its decode starts, it is compatible with the saved cache again at the later append loop. That loop iterated all selected paths, adding both the decoded entry and the old cache entry. The cache date/reused-entry map could then replace the fresh payload/date during serialization. | The cache append loop considers only files outside the fixed decoded subset. A newly decoded path is emitted once and keeps its new measurement date. |
| Forced report output can overwrite the engine's stores | The valid album folder `<data>/catalog` maps under artist layout to `<data>/catalog.json`, exactly `store::catalog_path(data)`. With `--force`, existing report reads are bypassed; publication saves the catalog, then the report's atomic replacement overwrites it. Other reserved JSON names can collide in the same way. Atomic replacement prevents truncation/link following but does not distinguish a report from an engine store. | Preflight every selected report destination before decoding or publication. Resolve the parent directory and refuse the installation's reserved catalog/conclusions/sources/user/accounts/parental JSON names, including ASCII case variants. Reuse the existing store path functions; ordinary report names and destinations outside that installation's data directory retain their behavior. |

Three sibling regressions are prepared, not executed: `analyze_tests::cache_changes_during_another_decode_fail_without_replacing_the_existing_report`, `analyze_tests::a_cache_that_becomes_reusable_during_decode_cannot_replace_the_new_measurement`, and `analyze_tests::forced_artist_reports_cannot_replace_aede_state_files`. The first two use the existing progress callback to schedule changes to owned fixture copies exactly between planning and cache assembly; no sleeps or external music changes are used. The restored-cache case uses a genuine unmodified analysis, rather than a fabricated measurement sentinel. The destination regression checks refusal before decoding, byte-preserved catalog/audio, all reserved store paths, parent aliases/case controls and ordinary allowed filenames. Existing test declarations/assertions are unchanged in this pass; verified counts remain unchanged.

The trace establishes these interleavings and path equality without dynamic execution. It does not claim filesystem snapshot isolation, detection beyond the existing whole-second imported identity contract or a sandbox against hostile concurrent parent replacement. The native CLI and its typed HTTP worker share the corrected implementation and nonzero failure status; no separate client change is needed. No dependency, persistent format, credential, original audio/tag or branch/commit change is made. The earlier corrective tree and these unexecuted regressions still await final verification. Three demonstrated defects are corrected:

| Case | Source evidence | Correction |
| --- | --- | --- |
| An unavailable album aborts all native analysis before useful work | The preceding pass introduced unconditional canonicalization of every report parent in global preflight. A retained catalog may legitimately include an unmounted folder: its `canonicalize()?` aborts the whole batch, including available albums. The typed server worker always requests JSON reports, so this regression also affects administrative analysis. | Separate reserved-path refusal from parent I/O failure. Known collisions still fail before decoding; an unresolved parent is handled with the affected album instead of abandoning the batch. Every actual report publication revalidates its destination. Available albums retain their measurements/reports, missing album folders are not recreated, and the final result still reports failure. **This regression was introduced by the third interaction pass.** |
| Spectrogram rendering writes directly to the final destination | `spectrum::render` passes the final PNG path to FFmpeg with `-y`, both for the caption attempt and its fallback. A normal redraw can truncate an existing picture before failing, or follow a pre-existing PNG symlink to an unrelated account/state file. Unlike M3U/copy output, it has no staging or destination-type check. | Reuse `copy::TemporaryOutput`, preserving `.png` for format selection. Render both attempts into the private staging directory and publish only after a successful attempt. Existing destination links/special files are refused before work and before publication; ordinary errors discard staging while retaining the previous picture. |
| A failed spectrogram batch is reported as a successful server task | The CLI accumulates and displays render failures but unconditionally returns `Ok(())`. Main therefore exits successfully, and `jobs::Registry::finish` selects `Completed` from exit code zero, even when all requested pictures failed. Whole-library generation similarly relies on each stage's exit status. | Finish the selected batch, preserve completed images, then return an error when any render failed. Existing job/generation consumers now receive a nonzero result without parsing terminal text. Empty/current selections and fully successful batches keep success. |

The direct-output risk is also corroborated by primary [FFmpeg file-protocol source](https://ffmpeg.org/doxygen/trunk/libavformat_2file_8c_source.html): write-mode file opening enables truncation by default and does not request no-follow protection. This is source evidence, not an execution against the installed encoder. The correction does not claim protection against arbitrary hostile concurrent parent-directory replacement; it uses the existing, qualified temporary-output policy. Cancellation by a killed process can leave a staging directory, but a partial rendering is never intentionally published as the final picture.

Four sibling regression declarations are prepared, **not executed**:

- `analyze_tests::an_unavailable_album_does_not_block_other_catalogued_folders`: owned scanned fixture folders, one made unavailable, surviving album decoding/report/conclusion, byte-preserved audio, retained roots and nonzero final result.
- `spectrum_tests::rendering_publishes_only_a_completed_picture_after_caption_fallback` in core: successful and failed caption fallback, unchanged final bytes throughout rendering, preserved PNG extension and cleanup on ordinary return.
- `spectrum_tests::rendering_refuses_destination_links_before_work_and_before_publication` in core (Unix): static and late destination links, untouched private bytes, refused publication and staging cleanup.
- `commands::spectrum::tests::a_failed_picture_fails_the_batch_without_abandoning_other_tracks`: injectable renderer failure, every selection attempted, successful pictures retained, nonzero batch outcome and a successful control batch.

The injected renderers test publication/orchestration boundaries, not audio decoding or real FFmpeg behavior. No existing test declaration/assertion is removed or disabled.
