# Aède — Current state

## Project status

Aède 0.7.5 is the local-first music engine and CLI, with a separate Tauri server App. FlacCompagnon core is pinned to the reviewed native-codec source recorded in Cargo.lock. The [roadmap](../design/roadmap.md) remains authoritative: M0 catalogue/storage and M1 enrichment are implemented; M2 API/persistence is implemented with deployment capacity acceptance pending; M3 playback is software-hardened with physical/platform acceptance pending; M4 has initial network-device profiles.

The catalogue is graph-based and common to installation accounts. Personal annotations, ratings, favourites, tags, collections, histories, preferences, checkpoints and achievements remain owner-private. Accounts use stable identity, role/session checks and independent protected storage. Parental policies retain exclusive supervisor locks, civil-time windows and bounded listening leases. Guest use remains unrestricted by design. See [accounts](../design/accounts.md), [isolation](account-isolation.md) and [parental controls](../server/parental.md).

## Delivered interfaces

- Spectrograms use the shared FlacCompagnon Rust PNG renderer: green, 1200×627 standard plot, 1800×940 large plot, application signature and actual decoded audio properties. PCM generation needs no external tool; The admitted DSD64/128 candidate also decodes natively; other profiles retain explicit compatibility limits. The server PNG contract is unchanged, so Phémios needs its next embedded-engine rebuild rather than a spectrum protocol change. See [spectrograms](../spectrograms.md).

- The CLI scans/browses/queries the local graph, preserves deterministic identities and attributed source claims, checks integrity, imports analyses and explicitly generates sidecars/exports. Retained analysis/source forgetting requires confirmation or explicit `--yes`; [script migration](../cli/options.md#forgetting-data-and-migrating-scripts) explains the changed unattended contract. Source audio/tags are never changed.
- The HTTP/JSON/WebSocket server provides bounded catalogue reads, private routes, task activity and authenticated PCM. Jobs retain completed work and can survive client disconnection; process-local task registries do not imply restart persistence. See [API](../api.md), [route inventory](../../crates/aede-server/README.md) and [jobs](../server/jobs.md).
- Administrative MusicBrainz review exposes the existing durable accept/reject/undo rules with optimistic revisions and explicit exact-artist biography tasks; see [source review](../server/source-review.md). Pending native-client rebuild/live-provider acceptance remains distinct from fixture verification.
- Explicit biography enrichment follows the requested client language, including previously cached English/fallback text, and retains completed language preferences, source attribution and rejection decisions. Labels expose an additive cached-logo hint and artwork route without provider access during browsing. See [source review](../server/source-review.md#biography-language-and-retained-answers) and [label logos](../server/presentation.md#label-logos).
- Native presentation supports source-qualified artist/album/track/label/composer navigation, public cache projections, private dynamic browsing collections, missing-discography suggestions, analysis/report reconstruction, lyrics, waveforms and original-file exports. Capability names distinguish old running engines from confirmed empty data. See [presentation](../server/presentation.md).
- The [server App](../desktop.md) uses isolated application data, local HTTPS, editable roots/scans, public connection-profile export and bounded sanitized status/log views. Header navigation retains the three views; stopped-server maintenance renews generated administrator credentials with a recoverable intent, opens the App-owned data folder, or explicitly selects an empty store while archiving the prior configuration and retaining its data. CLI data is separate. [Parent-owned embedding](../server/desktop.md) supports Phémios over ephemeral HTTPS/WSS with process-only certificate trust.
- Local playback supports without-effects, DSP and a narrowly admitted direct-ALSA strict bit-perfect route. Native remote PCM uses client consumed-frame ACKs; local history has a different submitted/estimated timing boundary. See [playback](../design/playback.md), [DSP](dsp-review.md) and [acceptance](bit-perfect-acceptance.md).
- UPnP, OpenHome, Cast and SlimProto reuse `aede-devices`. Authenticated graphical profiles use exact-login ownership, a finite queue and heartbeat leases; physical interoperability remains separate. See [devices](../server/devices.md).

The bilingual [shared architecture guide](../manual/ecosystem.md) presents the three applications and their reusable crates with localized UML overview/detail diagrams and a complete ecosystem view. The [shared audio foundation](../design/shared-audio.md) supplies common PCM primitives across the three repositories. It reuses the existing DSP and provides an optional minimal FlacCompagnon player without Aède accounts/server or loudness effects. Client native build preparation automatically selects the latest published stable Aède release and records its exact SHA in workspace dependencies and lockfiles. Each GitHub run freezes one selection across platforms; Phémios builds its embedded engine from that same source. No sibling checkout is required. Published `v0.7.1` includes the shared crates that were absent from `v0.6.1`. The 0.7.5 candidate adds cached label-logo presentation and language-aware biography refreshes while retaining the stable collection identities introduced in 0.7.4, the failure-close correction and the Linux ARM64 musl CLI archive whose native tests run in the release workflow; a draft is not selected by stable-source preparation. Native platform builds remain separate acceptance checks.

Aède 0.7.4 collection identity uses opaque persistent IDs, owner-scoped ID selectors and the `collection_identity` capability. Personal stores read formats 1/2 and write format 3 to prevent older engines silently dropping IDs. See [migration and downgrade limits](../server/presentation.md#stable-collection-identity). New collections propagate OS-random generation errors; name-based CLI/API compatibility remains available.

The unpublished [native DSD input](../design/native-dsd.md) adds progressive DSF/DFF DSD64/128 mono/stereo decoding to the shared audio crate, with distinct wideband measurement and filtered listening profiles. Catalogue admission and existing PCM playback reuse it; client stable-source preparation still selects the previous published source until a coordinated release. The candidate spectrogram adapter reuses FlacCompagnon's Rust FFT/PNG component, with atomic source-stamped images and lazy external decoding only for codecs outside native support. Its composite source checks do not change the published dependency pins; see [spectrograms](../spectrograms.md).

The [global audio format matrix](../design/audio-format-matrix.md) inventories catalogue, playback, analysis/spectrogram and external-tool boundaries across Aède, Phémios and FlacCompagnon. It records the remaining corpus and native-codec work without promising that an entire recognized codec family is already qualified. The follow-up includes the experimental terminal player's remaining ffplay dependency; native musl output/packaging must be qualified before removing its current output. The approved candidate Opus adapter reuses statically linked libopus for complete family-zero/family-one streams with one through eight named speakers in shared playback and FC analysis/spectrograms; unsupported profiles keep explicit boundaries. This remains unpublished alongside the candidate DSD APIs.

The follow-up ALAC candidate resolves missing MP4 channel/precision hints and high-rate placeholders through a common codec-configuration inspector reused by metadata browsing and FC analysis. ALAC16 mono/44.1 kHz and ALAC24 stereo/96 kHz have exact native sample, duration, seek and spectral-resolver coverage. The next AAC-LC candidate shares bounded MP4 edit admission and packet trimming across playback, FC analysis and Rust spectrograms. Known LC mono/stereo properties, exact playable duration, pre-roll, seeks, cancellation and missing-tail refusal have fixture coverage; unqualified AAC profiles/edits retain explicit compatibility. These remain unpublished APIs, not blanket ALAC/AAC admission.

The next unpublished [additional-codec candidate](../design/native-additional-codecs.md) adds bounded shared WavPack/Musepack/Speex/APE readers and native Rust spectrogram inputs in Aède and FlacCompagnon. The shared original-PCM16 APE reader now provides retained-file admission and exact compressed-frame seeking for Phémios CUE images; full original-integer analysis and unqualified profiles/platforms remain explicit separate boundaries. Approved static reference C calls are isolated; browser DSP-only builds do not include them.

The historical APE extension uses the explicitly approved static Monkey's Audio 13.43 SDK for bounded 3.80–3.98 inputs, while retaining the Rust backend from 3.99. Shared normalized playback/spectral input and original PCM16 CUE seeking use the same protected read-only source and full-frame CRC boundary. Independent historical PCM/seek evidence and remaining profile/platform limits are recorded in [additional codecs](../design/native-additional-codecs.md#historical-ape-decoding). No App/embedded-engine rebuild or publication is implied.

The local [native-audio qualification](../design/native-audio-platform-validation.md) corrects Linux GNU/musl and Windows GNU C/C++ builds for x64/ARM64 while retaining explicit target-execution/MSVC limits. Catalogue DSD inspection now preserves unsupported source clocks/DSF layouts with derived native listening/measurement capabilities. Phémios presents those source facts and converted PCM separately, with local previews of both shared Rust PNG sizes. Installed-App delivery remains separate.

The next native surround candidate admits Opus mapping family one (1–8 channels) through an approved isolated FFI over the existing static libopus, plus explicitly described Apple ALAC layouts (3–8 channels). Original distinct-speaker references cover output order and exact counted length; native playback/seek and spectral resolvers exercise these profiles. Unspecified layouts, other AAC profiles and the remaining output/platform boundaries are not silently admitted. See [surround follow-up](../design/shared-audio.md#native-surround-follow-up).

The unpublished [DoP candidate](../design/dop-output.md) adds bounded original-bit DSF/DFF transport and approved dedicated CoreAudio HAL, WASAPI exclusive/raw and ALSA hardware backends. The CLI, FlacCompagnon preview and native Phémios select DoP explicitly with an exact compatible-DAC ID. The server transports authenticated original words under `dsd_original_playback`; Phémios owns output and exact-bit resume. Browser output remains PCM. Linux GNU enables ALSA; custom musl builds can opt into `dop-alsa` with target libasound. No App rebuild or shared-source publication is implied. DAC recognition, driver-specific formats and physical bit identity remain hardware acceptance.

## Remaining acceptance and limits

The [dependency audit](dependency-audit.md) records the approved Windows `clipboard-win` 5.4.3 and engine/App Tokio 1.53.3 corrections. Both complete gates passed again on macOS on 2026-10-23, retaining the engine's 2,934 Rust tests and the App's 76 Rust, 38 Vitest and 2 Node cases. The Tokio advisory no longer matches either lockfile. The [Windows release correction](windows-release-validation.md) preserves raw root traversal until ancestor validation, repairs portable fixtures/preview expectations and removes Unix-only mutable bindings from the Windows App build. The correction passed all six jobs in [native CI run 40027173576](https://github.com/craft-and-code/aede/actions/runs/40027173576), including both Windows-only regressions and desktop warnings-denied Clippy. Windows clipboard and interactive console/output acceptance remain pending. RustSec policies retain empty ignore lists: GLib unsoundness, `paste`/`proc-macro-error` maintenance findings and the documented cargo-deny internal diagnostics remain visible; the two cargo-deny workspace checks still fail.

The [PCM failure-close correction](m3-review.md#failure-notification-and-close-handshake) adds seven regressions and a bounded, shutdown-interruptible peer close handshake. The original MD5 cases remain unchanged; late cleanup ACKs cannot change sealed history or start the next source. Host gates and 90 repeated MD5/close cases pass. The correction passed all six jobs in [native CI run 40069139533](https://github.com/craft-and-code/aede/actions/runs/40069139533) on exact source `ec9da48cb70a4d0255abe3f512adbd2d4cb351db`, including the historical MD5 case, all seven new regressions and the retained shutdown regression on Linux GNU, Windows and macOS. Linux passed 2,943 Rust cases with one pre-existing ignored physical ALSA test; Windows passed 2,744 with none ignored. CLI jobs use Rust 1.89. The run validates this corrected source without proving the precise cause of the historical intermittent EOF. The published v0.7.1 tag and packages retain the previous source; v0.7.2 retains the failure-close correction, and v0.7.3 adds Linux ARM64 packaging without moving either prior tag.

Linux CLI release targets include x86_64 and ARM64 (`aarch64-unknown-linux-musl`), each built and tested on a matching native GitHub runner before packaging. Both musl archives need ffplay for local playback; headless catalogue/server operations do not. The desktop App remains Linux x86_64 only; ARM32 is not packaged. A workflow target is not evidence of successful execution until its tagged job passes.

Physical gapless/digital bit-perfect output, Windows console/device behavior, strict ALSA runtime, target-NAS memory/throughput/concurrent-client capacity and real LAN renderers require their own environments. Synthetic signals, metadata harnesses and software loopbacks do not certify those targets. Docker/service deployment, richer device registries and additional queue/session designs remain roadmap work.

No metadata-only browse initiates enrichment. Public caches/roots stay common; the trusted OS operator and installation token are outside account privacy. JSON stores, shared writer budgets, filesystem TOCTOU constraints and failure-preserving publication remain explicit. SQLite is a measured option, not an M2 requirement.
