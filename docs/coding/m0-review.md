## Demonstrated defects

### Native metadata boundaries

**ID3v2.4 unsynchronisation was applied at the wrong scope.** A Latin-1 title containing an unsynchronised byte sequence split into two values when only the frame flag was set. With the global flag set, whole-tag reversal changed encoded frame lengths and lost the following artist frame. Version 2.4 now consumes each encoded frame before reversing its payload; version 2.3 keeps its whole-tag transformation. Two regressions failed before correction; a third preserves version 2.3 behavior. The implementation follows the [ID3v2.4 frame-size and unsynchronisation rules](https://id3.org/id3v2.4.0-structure).

**Ogg payload bytes could replace a page's duration.** A page with granule 48,000 containing a same-serial `OggS` header-shaped byte sequence with granule 4,800,000 produced 100 seconds instead of one second. Duration lookup now reuses complete page boundaries and skips their payloads. Independent rereading then reproduced an incomplete false header in a tail window starting inside a preceding page; the tail reader resumes past that incomplete candidate to reach the real final page. Both cases have regressions. These are synthetic container fixtures, with CRC fields added during the second pass below; they are not independently codec-valid recordings. Real Opus/Vorbis fixtures are tested separately. The bounded duration lookup remains distinct from whole-file [Ogg CRC verification](../integrity.md). See the [Ogg page structure](https://www.rfc-editor.org/rfc/rfc3533.html).

### Scan, graph construction and diagnostics

**Plural artists were diagnosed as absent.** A file with valid `ARTISTS` but no singular `ARTIST` was built into the graph correctly yet received `MissingArtist`. The diagnostic now follows the builder's plural-first fallback.

**Original dates were ignored by diagnostics.** A valid `ORIGINALDATE` supplied the graph's year while `doctor` reported a missing date. The diagnostic now follows the same original-date-first fallback.

**A label identifier leaked to an unrelated second label.** With two label names and only one indexed identifier, the builder reused that first identifier for the second name. Identifiers now pair only with their corresponding positions; the unpaired label retains its local identity.

**A late release-group identity was incomplete.** When only a later track supplied a release-group MBID, the release acquired its internal group ID but its public MBID stayed empty. Both projections now agree. The regression also retains the first accepted identity when a third track disagrees.

**Pre-epoch modifications collapsed into a reusable zero identity.** Two distinct negative modification times with the same path and size both became unsigned `mtime=0` with fraction zero, so the second scan reused metadata instead of reading it. Unavailable/pre-epoch times now omit usable precision and force rereading. Conclusions also refuse attachment through an imprecise fallback zero, while retaining stored evidence unchanged; exact epoch timestamps and legacy positive timestamps remain supported. Separate scan/conclusion regressions preserve this distinction without changing the storage format.

**Unknown durations became evidence of duplicate albums.** `None` was converted to zero before the three-second comparison, linking unknown/zero-length tracks as duplicates and advertising recoverable space. Corresponding durations must now be known and positive. The regression covers absent/zero durations and retains a legitimate two-second difference. Inference rule version 4 rebuilds older tag-derived relations on load, preserving files, durations and the storage format without a source rescan.

### CLI queries and personal interchange

**Literal filters lost punctuation.** An artist such as `Rock'n'roll` could return no result, parentheses could become grammar, and embedded double quotes were discarded. The shared filter helper now preserves literal text using the query tokenizer's existing adjacent quoting rules. A behavioral regression covers exact artist/genre/label/comment results. Independent AST checking additionally exercised 96,624 field/value combinations without loss; this is a bounded generated probe, not a general parser proof.

**Rules imports admitted private media state outside their contract.** A syntactically valid rules bundle could carry client preferences, playlists, scrobbles or playback states into `user::merge`. All four tables are now refused before merging or writing either store. A regression injects each table and verifies unchanged personal/source bytes, including another owner's existing annotation. This is a bundle-scope violation, not evidence that the authenticated server exposed another account.

**Personal import bypassed the raw-input budget.** A small valid personal JSON document followed by more than 64 MiB of whitespace was accepted through `notes --import`, although the ordinary personal-store loader refused it. Import now reuses that bounded loader. The regression verifies refusal before writing, with chunked fixture construction rather than a giant test allocation.

**Machine query exports ignored pagination.** `query --json --offset 1` still returned the only track; invalid limits bypassed validation. Query and collection execution now validate the window first and pass the selected slice to JSON/CSV/M3U output. Human output still windows once. Regressions cover both commands/formats and invalid bounds.

**An output path without a format was silently ignored.** For example, `albums --output result` succeeded without creating the requested output. Selection output and human listing branches now reuse the existing explicit refusal. Regressions include empty favourites and selection/detail/listing paths.

### Copy/conversion

**A completed resume unnecessarily required FFmpeg.** The CLI refused compressed-copy resumption without FFmpeg even when every nonempty derived output already existed and was supposed to be skipped. Tool discovery now depends on encodes actually needed. New outputs, `--replace` and `--verify-existing` still require the encoder, before writes. Public CLI and worker regressions demonstrate the refusal and successful safe resume.

**Encoder diagnostics accumulated unbounded memory.** `Command::output` retained all stdout/stderr even though only the end of stderr was used. A confined fake encoder emitting 16 MiB on each stream returned a 16,777,246-byte error. Conversion now discards stdout and completely drains stderr while retaining a 4096-byte tail, sharing the existing decoder helper. Read errors terminate and reap the child; successful/failing publication preserves the existing output and original source as appropriate. Independent rereading found that `Interrupted` needed the retry behavior of `read_to_end`; a fault-injecting `Read` regression now preserves it. No real signal-based failure is claimed.

## Resource measurements

### Diagnostic graph traversal

Duplicate/other-edition diagnostics previously traversed every relation once per release. They now traverse release-to-release edges once, retaining pair deduplication and the same diagnostics. The repository example can be run with:

```sh
cargo run --offline -p aede-core --release --example doctor_bench
```

Before/after measurement compiled the same harness with `rustc --edition=2024 -C opt-level=3 -C lto=thin`, linking the respective existing release `aede-core` artifacts. This is a matched harness comparison, not a claim to rebuild both full workspaces with independently verified identical compiler flags. It uses the same in-memory synthetic graph and five timed diagnostic runs per size. Construction is outside the timed region; each result is checked empty, with one artist, one track per distinct album and eight relations per album (8,000, 16,000 and 32,000 observed edges). Median times on this Mac:

| Albums | Before | After |
| ---: | ---: | ---: |
| 1,000 | 12.373 ms | 2.502 ms |
| 2,000 | 44.559 ms | 4.925 ms |
| 4,000 | 167.560 ms | 10.613 ms |

The 4,000-album probe improves about 15.8×. This measures that diagnostic workload, not whole-app startup, large real-library memory or target-NAS acceptance.

### Verbose encoder output

The same confined 32 MiB-output probe measured maximum process RSS of 76,840,960 bytes before and 7,274,496 bytes after; elapsed times were 0.78 and 0.76 seconds. Measurement used `/usr/bin/time -l` on the `aede-core` unit-test binary in test/debug profile, running only `copy::transcode::tests::excessive_encoder_diagnostics_are_drained_and_bounded_without_publishing_output` with `--exact` and `--nocapture`. The binary was rebuilt with the same Cargo command/profile for each version; each version had one instrumented run. This calls the real `copy::transcode::convert` API with the fake encoder, not the CLI or entire application. The returned diagnostic is bounded, its final cause survives, the child exits and temporary files are cleaned. This single illustrative output-capture measurement is not an audio-encoding throughput benchmark.

### Qualifications retained explicitly

- The AIFC IMA4 case concerns misleading guessed properties of an unsupported compressed codec. The correction leaves those properties unknown; it does not add IMA4 support or establish a playback fault in documented PCM AIFF/AIFC. Integer/float PCM controls remain unchanged.
- The original Ogg regressions are structural synthetic fixtures. A newly generated packet-padding probe decodes identically and reproduces the original reader's duration error, but nonzero Opus audio padding must be accepted by decoders while encoders must emit zero padding; it is not conforming encoder output or evidence of ordinary-library prevalence. See [RFC 6716 section 3.2.5](https://www.rfc-editor.org/rfc/rfc6716.html#section-3.2.5).
- A stronger, separately identified CRC-discrimination control uses binary OpusTags padding explicitly permitted by [RFC 7845 section 5.2](https://www.rfc-editor.org/rfc/rfc7845.html#section-5.2). Complete FFmpeg decodes give the same PCM MD5 (`5dbe2b2c34408ec41a16c025542b82e9`). A reconstructed current page walker with only CRC/version admission removed reports 99,993 ms, versus 1,050 ms with the guard. The exact original `f47408fb` reader reports 1,050 ms on this particular control. This supports the later guard against a page-walker regression; **the reconstructed variant is not an archived first-pass checkout and is not presented as such**.
- Unknown source precision refusal intentionally also excludes some encodes that might happen to preserve samples. It establishes a conservative guarantee, rather than pretending to know missing source information. An unsupported installed FFmpeg encoder is an environmental capability limit; the absent `libvorbis` encoder in these probes is not counted as an Aède defect.
- The owner-counter regression requires valid persisted/imported zero counters. The ordinary recording path starts new counters at one. Invalid commands and deliberate empty results are not counted as additional product defects.

No previously confirmed correction is withdrawn after these checks. The scope qualifications above remain part of the evidence, rather than being erased by a passing suite. No new performance improvement, universal parser correctness, security certification, native Linux/Windows acceptance or minimum-toolchain run is claimed.
