# Missing studio albums and private decisions

`GET /api/me/v1/missing` reads trusted cached MusicBrainz discographies through the same `aede-core::missing` policy used by `aede missing`. Missing entries are attributed release groups, not local release editions: they have no playable tracks or physical folder. Only artists with principal albums are considered. Existing release-group IDs or normalized titles remove owned albums from the derived answer; the default profile includes studio albums only. Reading never fetches external data.

The authenticated owner's response accepts only `offset`, `limit` (1–200) and `include_set_aside` (boolean, default false). Each item has `artist` (native reference), `artist_name`, `release_group` (MusicBrainz UUID), `title`, nullable `year`, `set_aside`, `source` and `url`. The envelope retains ordinary `items,total,offset,limit,scanned_at` fields. `include_set_aside=true` also returns this owner's hidden missing suggestions so a client can restore them.

`PUT /api/me/v1/missing` accepts exactly `{release_group:"UUID",set_aside:true|false}`, with no query. A user or administrator can hide a current missing studio-album suggestion, or restore a decision; auditors are refused. The shared locked personal writer retains the current owner and preserves corrupt stores. Repeated identical writes are idempotent; at most 4096 decisions per owner are accepted. UUID selection cannot hide a different same-name album. No source record, audio file, tag or catalog release is removed. Source discography refresh and ordinary additions recompute missing status without stale stored missing flags.

The route is owner-private on both HTTP and authenticated HTTPS, advertised as `missing_studio_albums` in status. It never accepts an owner, path or external URL. Busy, corrupt, revoked and unavailable states follow the existing personal-route failures. A client should explain an absent capability before offering writes to an older server.
